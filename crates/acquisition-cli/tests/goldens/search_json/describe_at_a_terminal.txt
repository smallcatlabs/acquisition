an answer, key by key
  query                        key         the text as understood, and its tree; a trade site search's report is `query.trade`, which the trade section explains
  set_aside                    key         under the corpus context, the query typed beside it
  scope                        key         what was searched
  scope.never_fetched          key         `never_fetched` counts the tabs, their pages and the characters a listing names and no fetch has filled, and no answer says what they hold, a count of none or of many
  scope.never_fetched_by_type  key         `never_fetched_by_type` is the same by tab type, a character's `character`
  scope.never_fetched_leagues  key         `never_fetched_leagues` names the leagues holding a never-fetched tab, the most first; characters never fetched are counted by type under `never_fetched_by_type`
  total                        key         the matches
  before                       key         where a request is sent back with the `count` it was printed with, and the `counted_at` basis it came from
  rows                         key         id, name, base, rarity, place by name and id — a tab's page with no name of its own has `name` null and its tab in `parent` — with the cell the item sits in (`place.cell`, GGG's x and y, in a tab or an inventory) and when that place was last fetched (`place.fetched_at`, in words `place.fetched_at_age`), and under membership all and removed when the item left (`removed_at`, in words `removed_at_age`), and the lines each term touched with their values, the term named by its `path` in `terms`, never the item's body, which is `show`
  view                         key         the view as it ran
  unmatched_leagues            key         the leagues of `scope.leagues` no match is in, beside a counts table or a cross keyed by `league`
  view.rows.next               key         rows past the limit are counted in `view.rows.left_out`, and `view.rows.next` is the request for the rows after
  zero                         key         in place of rows when the total is zero
  terms                        key         for each term how many items matched, failed, lacked the thing or were undecided — each term alone over every item in scope, never over the matches, which are `total`; a pattern term's `resolved` is what it matched there, its `rest.denominator` `scope`
  basis                        key         what the answer was computed from
  snapshot_at_age              key         when the facts the answer read were last written (`basis.snapshot.at`), in words at the answer's time
  before_snapshot_at_age       key         the same for a `before`'s `counted_at`
  request                      key         a count holds the request that returns exactly its members where a next step hangs on it — what is undecided, what holds only together, what a key could not place (`none`, `undecided`), what an ambiguous trade clause's other reading adds or drops, and each term's matched where nothing matched — with `denominator`, what the request searches
