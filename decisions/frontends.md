# Decisions — Frontends and output

Part of the decision registry (`AGENTS.md`, "Cross-cutting rulings"): the rulings that bind the CLI, the MCP server, `dash`, rendering, `--json`, agent-boundary defaults, and the verbs every frontend shares (`acquisition-cli`, `acquisition-mcp`, `acquisition-verbs`). Read this before touching that code; the cross-cutting decisions and the invariants are in `AGENTS.md` and are always loaded. Same rules as there: one entry per ruling, in the form `tools/bothy.py`'s docstring states; the mechanism lives in the code's doc comments under the id.

## Frontends and output

- **C11 — The CLI's output is structured: `--json` on every command, the error path included.** A failure is `{"error": …}` on stdout with exit 1; a failed or cancelled job exits 1 in both modes; a command line the parser refuses is the same document with `kind: "usage"` and exit 2; a write refused for its revision is `kind: "conflict"` with `revision` as a field, on the CLI and the MCP. *Why:* the CLI is itself an API, which makes MCP and agent use nearly free. *Pinned:* `acquisition-cli/tests/seat_faults.rs`, the `c11_` test in `search_json.rs`.
- **C13 — The MCP server is a fourth thin client (`acq-mcp`, the official `rmcp` SDK over stdio), never in-process with the daemon.** It never kills or replaces a daemon and never spawns one in real mode, login being a human's act through the CLI; it spawns lazily in mock mode only. *Why:* daemon-hosted queries make the daemon an application server. *Pinned:* `acquisition-mcp/tests/plan_loop.rs`, `acquisition-mcp/tests/ggg_refusal.rs`.
- **C16 — The GUI is web rendering served over loopback by a Rust frontend; Tauri is the shell to add if a windowed app is wanted.** The page is presentation: it renders the documents the verbs produce and evaluates, sorts, filters and composes nothing itself (C46, shared semantics in Rust). A page holds no state the server cannot rebuild from the page's URL and one feed line: its identity is its URL, every document it holds carries its basis (C98), the basis is the only version there is, and the feed says only that a basis moved; a page rule that is semantics moves to the server and one that is presentation gets a browser-driven check. *Why:* item search, grid and filter views are a strength of web technology, and a loopback server is a strict subset of the Tauri path: a webview can point at the same server later, and the reverse is not true; a framework brings its own store and its own sequence number, and a page that holds state the basis does not label is a second version, the stale answer C48 forbids. *Pinned:* `tools/arch-check.sh` (the door grep); `acquisition-cli/tests/web.rs`: every page a golden of a verb's document, the state sentence by `c16_no_served_script_names_a_storage_cookie_or_history_api` (each listed script scanned, lexical, the rest the review's) and the basis by `c16_every_page_s_basis_line_is_its_documents_own`; the state sentence too by the recording seam of `acquisition-cli/tests/harness/mod.rs` (`Pages::page` and `Pages::redirect`: no recorded page sets a cookie or names a script off the one list).
- **C52 — An agent never clobbers intent it has not read.** `set_sync_policy` has no blind-replace form: replacing an existing policy names the revision it replaces, and `price_set` and `price_clear` take the same form. *Why:* an agent writes from a view that may be stale, and naming the revision turns staleness into a refusal. *Pinned:* `acquisition-mcp/tests/plan_loop.rs` (create-only compare-and-swap), `acquisition-mcp/tests/pricing_tools.rs`.
- **C53 — Output has three levels: default text is the decision view, `--expand` the audit view, JSON the contract.** Text is a function of JSON; grouping is presentation, never authorization. Default text states repeated context once, leaves out prose and provenance that do not change the next decision, opens with one answer and ends with the next action. Ten or fewer entities are listed, more are counted. In JSON the same number is the default: a list of like entities stands beside its counts, holds ten unless `limit` names more or `expand` asks for all, says how many it left out and, where the maker continues, the request that continues it; what an answer is for (a page's text, a plan's actions, a body asked for, a `describe` section) is never a list and never cut. The number is held once, and every maker applies it. A failure names target, cause and evidence; every nothing says which nothing. Ages are text, epochs are JSON, and an age the text prints stands in words beside its epoch in the JSON, made at the answer's own time, so a program keeps the fact and a reader keeps the words on every surface. Escapes only on a tty. JSON changes are additive. Stash tab ids sit in the last column. On a surface whose reader is a program (the MCP) the JSON is the text the reader gets: the decision view is the document's default shape, the audit view its `limit` and `expand`, and no second rendering stands between the reader and the contract. A document read at two densities is the decision view where nothing is named, on every surface and in every format, and the whole by name: `describe` with nothing named is the index — every entry's name and one line — in text and in JSON on the CLI and on the MCP, and `all` is everything whole; the additive clause protects shapes a program can use, and the whole stays reachable by name. Under `item` a rows answer holds at most the item rows' bound, whatever its `limit` names, and says the limit it applied; the rest are its continuation. *Why:* a reader decides from the first screen and audits only on request, and a 169 KB default is the audit view standing where the decision view belongs. *Pinned:* the `c53_` tests, the lowest in `acquisition-store/unit/tests/age.rs`; `acquisition-cli/tests/seat_faults.rs` (`describe_is_an_index_that_names_every_entry_and_says_how_to_read_one`) and `acquisition-mcp/tests/search_tools.rs` (`describe_is_the_clis_and_reads_no_store`), the bare shape on each surface.
- **C149 — Every answer and every refusal is one JSON object, its lists counted beside their rows.** A tool answers no bare array; the counts an answer's text prints stand in its JSON under the words C146 asks, so text is a function of JSON (C53). The one change that is not additive, taken at the alpha, whose consumers are the seats and the pages. *Why:* a seat made two counts by eye from a bare array of 65 rows and retracted both. *Pinned:* `acquisition-verbs/tests/documents.rs` (`c149_every_document_a_verb_returns_is_one_json_object`), `acquisition-cli/tests/store_answers.rs` (`c149_every_json_answer_the_step_wrapped_is_one_object`) and `acquisition-mcp/tests/search_tools.rs` (`c149_every_answer_the_step_wrapped_is_one_object`).
- **C115 — An answer leads with what bears on the question: the total and the view come before the terms block.** The terms block stays, without per-term request counts, and C93's meaning (absent is false, undecided is counted apart) stays. JSON carries a count's request only when routes are asked for. `tabs` in JSON takes the CLI's counts-first shape and a limit. *Why:* the MCP's default answer was larger than every seat harness's cut, and runs re-read the terms block instead of the answer. *Pinned:* `acquisition-search/tests/answer.rs`, `acquisition-cli/tests/search_json.rs`, `acquisition-mcp/tests/search_tools.rs`.
- **C116 — No id stands in user-facing text: no `C`, `S`, `N`, `T` or `Q` id in a help text, a reason, a note, a `says` or a refusal; the rule's words stand in its place.** Nor does a store name (`annotation`, `buyout`, a scope or key) stand in a refusal, which speaks the verb's words. *Why:* every seat met ids it could not look up, and a reason citing one read as a defect of the tool. *Pinned:* `acquisition-cli/tests/no_ids.rs` (any letter with digits).
- **C121 — An account that cannot be picked is refused in the protocol's words on every surface: `unknown_account` when the selector names one the index never held, `not_logged_in` when none is known or the one named has no session, `ambiguous_account` when it names several, or none among several with no main account taken (C187), each with `accounts`; the daemon answers alike.** *Why:* a name never held is a typo, not a login to make, and a program branching on `not_logged_in` would try one; one word per mistake, the same whether the verb went to the store or the daemon. *Pinned:* `acquisition-cli/tests/seat_faults.rs` (`an_account_that_cannot_be_picked_`), `acquisition-mcp/tests/tool_refusals.rs` (`a_tool_refusal_is_`) and the daemon's in `acquisition-daemon/src/daemon/tests/sessions.rs` (`c121_a_name_the_index_never_held_is_unknown_account_and_a_held_one_not_logged_in`).
- **C138 — The web UI's listener binds 127.0.0.1 on a random port, mints a per-launch token that every link and form action carries, refuses a request whose Host or Origin is not its own, serves no CORS, and mutates only by POST.** Its routes are private to its page and unversioned, carrying the verbs' own documents, so they are no third surface (C12, two surfaces). *Why:* any page a user visits can address a localhost port, and this one can cause GGG sends through apply; the token and the Host check are the Jupyter model, and what bounds the worst case is structure already in force: invariant 1 and the limiter govern every send, and a plan authorizes only the user's own tabs (C38, plans are binding). *Pinned:* `acquisition-cli/tests/web.rs`.
- **C139 — The web UI is `acq web`, a verb of the CLI crate: the server, its pages and the opener live in `acquisition-cli`, and `web` is a written channel (C65, provenance).** It reaches the daemon through the human door as every CLI verb does (C88, the real provider and the human) and links nothing the CLI does not (C1, the edges). *Why:* users have `acq`, the door and the browser opener are there, the skills run unchanged, and no new release artifact or Gatekeeper story opens; a later Tauri wrapper spawns the verb. *Pinned:* `acquisition-cli/tests/web.rs`, `tools/arch-check.sh` (the edges and the door grep).
- **C140 — Item art is the browser's: a web page names the icon URL the stored body carries, the user's browser fetches it from GGG's CDN, and the daemon and the tooling never do.** The CDN is a registered surface (C79, governed surfaces; `SURFACES.md`), and a page renders whole without the art. *Why:* invariant 1 governs daemon-originated traffic, and a browser's fetch of an image a page names is the browser's, as the authorize navigation is. *Pinned:* `acquisition-search/tests/rows.rs`, `acquisition-cli/tests/web.rs`.
- **C143 — A shared text speaks the request's own words, a view's field or a term, never a frontend's flag; a way on it names is a value each surface spells; an adapter may add its own spelling after them.** A refusal, a route, a continuation, a `describe` entry and a note alike: `sort` and `count` where the search crate refuses a count beside a sort, so one wording holds on a page, in an MCP result and at a terminal. A person's own act, such as signing in, stays a command, marked as a person's. *Why:* a sentence worded for one frontend reads as a defect on every other, a refusal or not, as ids did before C116 (no id in user-facing text). *Pinned:* `acquisition-search/tests/explain.rs`, `acquisition-mcp/tests/harness/mod.rs` (`c143_a_text_speaks_no_frontend`, every text the MCP tests meet).
- **C146 — A count says what it counts.** A number a frontend prints names what it counted, where it came from and what the reader can do next, in words a reader with no registry can parse, in its own sentence; a word naming a mechanism (`residue`, `unlifted`, `withheld`, a rank with no name) never stands alone; the same words stand on every surface the count stands, the text and the field's doc, and on the MCP in the `describe` entry the tool's description names in one line; a JSON field's name is the contract (C53) and does not change. *Why:* four seats stopped on the same six words and none resolved them from the tool alone. *Pinned:* `acquisition-cli/src/` (`c146_`, `c53_price_status_opens_with_one_line_and_ends_with_the_next_action`), `acquisition-plan/unit/tests/shop.rs` (`c74_the_link_codes_and_spoiler_titles_are_the_observed_shapes`).
- **C162 — Coverage and age are one derivation over a set of places, held once in the store and applied by every answer to its subject and, where wider, its scope.** It takes places with their observations (each location's kind, type, league and fetch, the listing bases, the items at each) and returns their count, the fetched and never fetched by type and league, the oldest and newest fetch with their locations, and each listing base with when it was seen, aged at the answer's time. A surface derives none of these for itself. It sits beside the age vocabulary and the read bound (C53, output levels), neutral, no policy in it (C39, neutral snapshots). *Why:* four surfaces derived coverage four ways, each reporting the age of what its struct held. *Pinned:* `acquisition-store/unit/tests/coverage.rs`, the `c162_` tests.
- **C163 — Every time a document carries has its words beside it.** A time a document serializes (seconds since 1970) has its age in words under the time's own name and `_age`, or under a path the document declares for it where the time sits in a value that is identity (C98, the basis) or a bound envelope (C38, the plan's); the words are made at the answer's time, or from a time of the document's own where its text measures so (C53, output levels); a null time says `never` or carries no words, as its maker says. A pin walks every document a verb returns and fails on a time, not null, with no words. *Why:* C53 words the ages a text prints, and a seat worked a date by hand from a time no text printed. *Pinned:* `acquisition-verbs/tests/documents.rs`; Unbuilt, #164.
- **C156 — A printed command is quoted for the shell it will be pasted into: the shell `ACQ_SHELL` declares, else the one the environment says.** `ACQ_SHELL` declares `posix`, `pwsh` (PowerShell 7.3 or newer), `powershell5` (Windows PowerShell 5.1) or `cmd` (cmd.exe), on any platform; a frontend refuses any other value, never reading it as unset. Undeclared, the shell is PowerShell 7.3 or newer on Windows outside Git Bash, which sets `MSYSTEM`, and a POSIX shell elsewhere; the binary's platform alone never decides. A JSON field whose value is one printed command stands beside what a program runs with no shell: the command's words, unquoted, or the request it spells. A refusal meeting what another shell left of a printed command names the declaration for that shell. No word is piped to dodge a shell. *Why:* detection cannot tell the two shells Windows ships from PowerShell 7 and a declaration can, while words a program runs need no quoting at all (a pipe for 5.1 corrupted every character past ASCII, the review of step words). *Pinned:* `acquisition-search/tests/answer.rs` (`a_printed_word_is_quoted_for_the_declared_shell`, over its table of shell words), `acquisition-cli/tests/error_kind.rs` (`c156_every_printed_word_reaches_the_program_whole_through_each_shell`), `acquisition-cli/src/terminal.rs` (`c156_`).
- **C168 — A page writes user-scoped intent as the verbs write it.** A page writes only through the verbs' door (C46, every frontend an adapter), by POST under the listener's token (C138, the listener), naming in its form the revision it replaces as the plan page carries its envelope (C38, plans are binding), and answers the one receipt (C78, a write returns its prior) or the one refusal (C11, the failure document); the first kind a page writes is the saved search (C167, user-scoped intent); an annotation (a price, the policy) is written from no page until its page is designed. *Why:* a browser is where a stale view could clobber, and the revision in the form makes staleness a refusal, as C52 (no blind replace) does for an agent. *Pinned:* the `c168_` tests in `acquisition-cli/tests/web.rs` (`c168_a_page_writes_a_saved_search_as_the_verbs_write_it`, `c168_a_stale_page_is_refused_and_offered_the_write_over_the_row_as_it_stands`, `c168_a_search_over_every_item_saves_opens_and_clears_through_the_forms`, `c168_each_malformed_write_or_opening_is_refused_and_writes_nothing`).
- **C187 — The world may hold a main account, taken where several accounts are known and none is named, and an answer that took it says so.** It is one row of user-scoped intent (C167) under the scope `default`, the account's uuid, set and cleared under revision compare-and-swap as a saved search is (C52), and only the verbs' account door reads it (C46): a job verb names the account it took to the daemon, which stays blind to intent (C34). The order is a named account (`--account`, `ACQ_ACCOUNT`, a tool's `account`), the main account where the index still holds it, the sole account known, else the refusal (C121), which says when a main account set is no longer known. An answer or a refusal that took it carries `main_account`, its name and uuid, which the verbs alone compose, and text says it where the answer names its account. One existing command changes: a job naming no account among several runs as the main account, and is refused `not_logged_in`, saying why that account, where it has no session, where before it ran as the one logged in. A default realm or league (#19) is another kind under the same scope. *Why:* the owner's store knows three accounts and he plays from one ("Gerwaric is my primary account, but I use all three"); in one morning his first `acq web` and two agent calls were refused for a name the world could hold. *Pinned:* the `c187_` tests in `acquisition-verbs/tests/documents.rs` (the door's order, the write and its receipt) and `acquisition-verbs/tests/daemon.rs` (a job's main account and its refusal), `acquisition-mcp/tests/saved_tools.rs` (the field the same at both doors).

## Not doing

What someone would propose and the project declines, each until the trigger it names or for good; the backlog is the repository's GitHub issues.

- A standalone queue TUI (`dash` as its own binary): not until a queue-monitoring slice opens.
- A web listener beyond loopback (a phone on the LAN): not until a design of its own rules its security story.
- Item counts beside `acq web`'s league select: not until one document carries the league list and the counts on one basis.
- The plan text's stale fold printed as a range when its ends are equal (`3 stale (13h–13h)`): not until a golden, a transcript or a seat captures one.
- A shorter mock stash window for the new-league rehearsal (`ACQ_MOCK_WINDOW_DIVISOR` on the harness's isolation list): not until a measurement shows that test setting the suite's wall time.
- A test seam into `acq web`'s script: not until a second script rule needs one; the page is likely to change. When one does, a rule that is semantics moves to the server and one that is presentation gets a browser-driven check.
- A front-end build step (Node, a bundler) in the gate: not until a spike inside a build step shows a page's complexity needs a framework; a vendored, pinned script file is tried first, and no framework is chosen in a design session (the owner, 2026-11-06, 4-full's design prompt).
- A login or a logout driven from a page: not until a user asks, login staying a person's act through the CLI (C13) with the page noticing one; a page login later is a route over the daemon's `auth_start` and the auth event 4-full's part 2 designs, and nothing in the daemon's flow changes for it (the owner, 2026-11-06: fine for now, as long as it is not hard to add later).
