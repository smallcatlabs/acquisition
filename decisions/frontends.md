# Decisions — Frontends and output

Part of the decision registry (`CONTEXT.md`, "Decisions — the registry"): the rulings that bind the CLI, the MCP server, `dash`, rendering, `--json`, agent-boundary defaults (`acquisition-cli`, `acquisition-mcp`). Read this before touching that code; the cross-cutting decisions and the invariants are in `CONTEXT.md` and are always loaded. Same rules as there: one entry per decision, stable `C<n>` ids never reused, the ruling verbatim, *Why:*, and pointers; the mechanism lives in the code's doc comments under the id.

## Frontends and output

- **C11 — CLI emits structured output** (`--json` on every command, the error path included: failures are `{"error": …}` on stdout with exit 1, and a failed or cancelled job exits 1 in both modes; a command line the parser refuses is the same document with `kind: "usage"` and the parser's exit 2). *Why:* the CLI is itself an API; makes MCP and agent use nearly free. *Pinned:* `acquisition-cli/tests/seat_faults.rs`. Amended 2026-10-13 (the usage and cancelled arms, the session's under the owner's delegation after the seat); 2026-10-19 (a write refused for its revision is `kind: "conflict"` with `revision` as a field, on both surfaces — the release seat's four runs parsed it out of prose; owner: "yes, go ahead").
- **C13 — The MCP server is a fourth thin client (`acquisition-mcp`, binary `acq-mcp`, official `rmcp` SDK over stdio), never in-process with the daemon.** It never kills or replaces a daemon and never spawns one in real mode (login is human, via the CLI); it lazy-spawns only in mock mode. *Why:* daemon-hosted queries make the daemon an application server. *Details:* `acquisition-mcp/src/main.rs` doc, C13. *Pinned:* `tests/plan_loop.rs`, `tests/ggg_refusal.rs`. Decided 2026-08-30.
- **C16 — Tauri for GUI** (webview frontend). *Why:* item search/grid/filter UIs are a strength of web tech; egui considered and passed on for data-heavy views.
- **C52 — An agent never clobbers intent it has not read.** `set_sync_policy` has no blind-replace form: replacing an existing policy must name the revision it replaces. Owner-revisable default, 2026-09-01. *Pinned:* `acquisition-mcp/tests/plan_loop.rs` (create-only CAS), `acquisition-mcp/tests/pricing_tools.rs` (`price_set` and `price_clear` take the same form).
- **C53 — Legible output has three levels: default text is the decision view, `--expand` is the audit view, and JSON is the contract.** Text remains a function of JSON; grouping is presentation, never authorization. Default text states repeated context once, omits prose and provenance that do not change the next decision, opens with one answer before detail, and ends with the next action. Ten or fewer entities are listed, more counted; failures name target, cause and evidence; every nothing says which nothing; ages are text, epochs JSON; escapes only on a tty; JSON changes are additive. Ruled 2026-09-02; amended 2026-09-03 after the live density reading (tab ids at right, pinned). *Details:* `plan_cmd.rs` doc, C53. *Pinned:* the `c53_` tests. *Evidence:* ledger row 2026-09-03.
- **C115 — The answer leads with what bears on the question: the total and the view before the terms block, and the JSON carries a count's request only when routes are asked, as the CLI already does.** The terms stay, without requests; C93's meaning stays, with no cascade number — the demotion is the fix, measured at the re-sit: no call spent, one re-read a run (parked). `tabs` in JSON takes the CLI's counts-first shape and a limit. *Why:* the MCP's default answer (about 31 KB) was over every seat runner's harness cut (about 30 KB), and three of four round-two runs re-read the terms block after its words were fixed twice. Owner, 2026-10-18, on the six as recommended: "I accept all 6. Go ahead." *Details:* note 38 at `16bba23e`, step 1. *Evidence:* `audits/trade-2026-10/seat/`.
- **C116 — No id in user-facing text: no `C`, `S`, `N`, `T` or `Q` id in a help text, a reason, a note, a `says` or a refusal; the rule's words stand in its place.** The trade report's rule (`the_reports_words_cite_no_record`) widened to every surface as one test. *Why:* every seat since the whole-CLI one met ids it could not look up ("they never helped"); the trade seat's price reason "(C81)" read as a defect of the tool to two runs. Owner, 2026-10-18, on the six as recommended: "I accept all 6. Go ahead." *Details:* note 38 at `16bba23e`, step 4. *Pinned:* `acquisition-cli/tests/no_ids.rs`, any letter with digits. Amended 2026-10-19: nor a store name (`annotation`, `buyout`, a scope/key) in a refusal, which speaks the verb's words (the release seat).

## Parked (do not build yet; each with its trigger)

Scope this area has deferred, under the rules of `CONTEXT.md`, "Parked".

- A term's count beside the total, read as a contradiction (each term counted alone over every league in scope, the query's league a term of its own: T4 at 30, `league=Standard sum(line("#% increased Rarity of Items found" source=explicit).arg1)>=30`, its sum term 30 beside a total of 27 — cli-opus call 26, cli-sonnet calls 14–15) → the terms block's words or what a term is counted over (C93, C115). Every re-sit run re-read it once and none spent a call on it (`audits/trade-2026-10/re-sit/`, count 1); owner, 2026-10-18: "Measured; park (Recommended)". Trigger: a run that spends a call on the terms block, or takes a term's count for the total.
- Queue-management UI (drag-to-reorder, per-job progress bars) → a rendering problem by construction. Trigger: the GUI.
- The read economy as a ruling (summary by default, filters, bounded detail) → surface design under C53 until then. Trigger: the first MCP pricing consumer's re-read record (the pricing tools, built at the release's step 1; the release seat is the first consumer).
- A request `acq-mcp` cannot read as JSON gets no reply: a tree of 123 nots or 62 groups, a message past 127 JSON levels by the depths measured, is dropped before any tool sees it, the server answering the next call and the caller waiting on this one; the search's own limit (`too_deep`, 32) is far under it and cannot reach it → the server's transport, an error reply where the id can be read. Trigger: a consumer that waits on such a call, or the MCP's next seat.
- Results over a subtree (today `list`, then `result` per child: hundreds for a real map tab) → results on the event channel as jobs finish, or a `results` verb. Trigger: a second consumer (GUI or MCP) showing which. Frontend boundary finding from `acq pull`, 2026-08-24.
- The MCP's `get_result`, `job_status` and `auth_status` with no daemon running (the CLI's three answer from the ledger and the index since 2026-10-13, `seat_faults.rs`; the MCP's still say only that none runs) → `acquisition-mcp`, over the same `Persisted::read_job`. Trigger: an MCP consumer that loses a detached job's result to the idle shutdown.
- A watch that waits for the daemon to return (`acq jobs --watch` ends when the daemon goes away: an observer never spawns, C10) → the GUI's subscriber, not the CLI's. Trigger: the GUI slice.
- Printed commands are POSIX-quoted (single quotes, `'\''` for an apostrophe; the tests run them through `sh`, Git for Windows' on Windows) → quoting for the shell that will run them. Trigger: a Windows agent that runs printed commands in PowerShell, where `'\''` does not read back.
- A standalone queue TUI (`dash` as its own binary) → a new frontend package linking the client crate; `Dashboard` reshaped for it (one fat response today). Trigger: the queue-monitoring TUI slice.
- The structured-error taxonomy beyond the additive `kind` (C85's closed `ErrorKind`) → the wire, with the GUI slice as its validating consumer (P2). Trigger: the GUI slice, or the owner asking for it first.
- A container's `price show` carries every item it holds (22 KB for a 30-item tab, 174 KB for a larger one: the release seat, mcp-sonnet call 25, cli-sonnet call 71) → a bound on `items_here` with the count, under C53. Trigger: the read economy's count — a run that re-reads a container's show for its cost, which none of the four did.
- The MCP's ages are epoch seconds alone (`taken_at`, `fetched_at`; a plan's `age_seconds` the one exception) → an age beside each stamp, or a clock in every scope. Trigger: a user's report, or a run that gets a date wrong from them (mcp-opus worked them by hand; mcp-sonnet trusted one clock over another).
- No MCP tool lists the refused bodies `store_status` counts (`acq store refused` has no twin) → a `store_refused` tool over the same read. Trigger: a user who needs the list from an agent.
- The shared refusals name the CLI's flags and verbs in an MCP session (`--realm`, `--if-revision`, `acq price show`), by the brief's rule that they are the CLI's words → a surface-aware rendering of the one refusal. Every release-seat run recovered through the `offers` or the parameter text. Trigger: a run that fails to recover from one.
- A sticky default realm, and a default league (the owner's idea, 2026-09-18) → the adapters, never the model: a CLI knob, a GUI's dropdown or an MCP default supplies the scope a request omits, and the answer prints it (C96); persisted across sessions it is user-scoped intent (`decisions/store.md`, the `user.db` park). Trigger: the GUI's realm control — the owner's own seat is the GUI's, and an agent driving the CLI states the scope each time (2026-09-25).
