# Decisions — Frontends and output

Part of the decision registry (`AGENTS.md`, "Cross-cutting rulings"): the rulings that bind the CLI, the MCP server, `dash`, rendering, `--json`, agent-boundary defaults (`acquisition-cli`, `acquisition-mcp`). Read this before touching that code; the cross-cutting decisions and the invariants are in `AGENTS.md` and are always loaded. Same rules as there: one entry per ruling, in the form `tools/bothy.py`'s docstring states; the mechanism lives in the code's doc comments under the id.

## Frontends and output

- **C11 — The CLI's output is structured: `--json` on every command, the error path included.** A failure is `{"error": …}` on stdout with exit 1; a failed or cancelled job exits 1 in both modes; a command line the parser refuses is the same document with `kind: "usage"` and exit 2; a write refused for its revision is `kind: "conflict"` with `revision` as a field, on the CLI and the MCP. *Why:* the CLI is itself an API, which makes MCP and agent use nearly free. *Pinned:* `acquisition-cli/tests/seat_faults.rs`, the `c11_` test in `search_json.rs`.
- **C13 — The MCP server is a fourth thin client (`acq-mcp`, the official `rmcp` SDK over stdio), never in-process with the daemon.** It never kills or replaces a daemon and never spawns one in real mode, login being a human's act through the CLI; it spawns lazily in mock mode only. *Why:* daemon-hosted queries make the daemon an application server. *Pinned:* `acquisition-mcp/tests/plan_loop.rs`, `acquisition-mcp/tests/ggg_refusal.rs`.
- **C16 — The GUI is web rendering served over loopback by a Rust frontend; Tauri is the shell to add if a windowed app is wanted.** The page is presentation: it renders the documents the verbs produce and evaluates, sorts, filters and composes nothing itself (C46, shared semantics in Rust). *Why:* item search, grid and filter views are a strength of web technology, and a loopback server is a strict subset of the Tauri path: a webview can point at the same server later, and the reverse is not true. *Pinned:* nothing yet.
- **C52 — An agent never clobbers intent it has not read.** `set_sync_policy` has no blind-replace form: replacing an existing policy names the revision it replaces, and `price_set` and `price_clear` take the same form. *Why:* an agent writes from a view that may be stale, and naming the revision turns staleness into a refusal. *Pinned:* `acquisition-mcp/tests/plan_loop.rs` (create-only compare-and-swap), `acquisition-mcp/tests/pricing_tools.rs`.
- **C53 — Output has three levels: default text is the decision view, `--expand` the audit view, JSON the contract.** Text is a function of JSON; grouping is presentation, never authorization. Default text states repeated context once, leaves out prose and provenance that do not change the next decision, opens with one answer and ends with the next action. Ten or fewer entities are listed, more are counted. A failure names target, cause and evidence; every nothing says which nothing. Ages are text, epochs are JSON. Escapes only on a tty. JSON changes are additive. Stash tab ids sit in the last column. *Why:* a reader decides from the first screen and audits only on request. *Pinned:* the `c53_` tests.
- **C115 — An answer leads with what bears on the question: the total and the view come before the terms block.** The terms block stays, without per-term request counts, and C93's meaning (absent is false, undecided is counted apart) stays. JSON carries a count's request only when routes are asked for. `tabs` in JSON takes the CLI's counts-first shape and a limit. *Why:* the MCP's default answer was larger than every seat harness's cut, and runs re-read the terms block instead of the answer. *Pinned:* `acquisition-search/tests/answer.rs`, `acquisition-cli/tests/search_json.rs`, `acquisition-mcp/tests/search_tools.rs`.
- **C116 — No id stands in user-facing text: no `C`, `S`, `N`, `T` or `Q` id in a help text, a reason, a note, a `says` or a refusal; the rule's words stand in its place.** Nor does a store name (`annotation`, `buyout`, a scope or key) stand in a refusal, which speaks the verb's words. *Why:* every seat met ids it could not look up, and a reason citing one read as a defect of the tool. *Pinned:* `acquisition-cli/tests/no_ids.rs` (any letter with digits).
- **C121 — An account that cannot be picked is refused in the protocol's words on every surface: `not_logged_in` when no account is known or the selector names none the index holds, `ambiguous_account` when it names several or names none among several, each with `accounts`, the names known or to pick from.** *Why:* the daemon already answers a named account it has no session for as `not_logged_in` (C85, the closed kinds), so one word for one mistake lets an agent branch the same way whether the verb went to the store or the daemon. *Pinned:* `acquisition-cli/tests/seat_faults.rs` (`an_account_that_cannot_be_picked_`), `acquisition-mcp/tests/tool_refusals.rs` (`a_tool_refusal_is_`), `acquisition-mcp/tests/search_tools.rs` (`the_requests_account_selects_the_store`).
- **C138 — The web UI's listener binds 127.0.0.1 on a random port, mints a per-launch token that every link and form action carries, refuses a request whose Host or Origin is not its own, serves no CORS, and mutates only by POST.** Its routes are private to its page and unversioned, carrying the verbs' own documents, so they are no third surface (C12, two surfaces). *Why:* any page a user visits can address a localhost port, and this one can cause GGG sends through apply; the token and the Host check are the Jupyter model, and what bounds the worst case is structure already in force: invariant 1 and the limiter govern every send, and a plan authorizes only the user's own tabs (C38, plans are binding). *Pinned:* nothing yet.
- **C139 — The web UI is `acq web`, a verb of the CLI crate: the server, its pages and the opener live in `acquisition-cli`, and `web` is a written channel (C65, provenance).** It reaches the daemon through the human door as every CLI verb does (C88, the real provider and the human) and links nothing the CLI does not (C1, the edges). *Why:* users have `acq`, the door and the browser opener are there, the skills run unchanged, and no new release artifact or Gatekeeper story opens; a later Tauri wrapper spawns the verb. *Pinned:* nothing yet.
- **C140 — Item art is the browser's: a web page names the icon URL the stored body carries, the user's browser fetches it from GGG's CDN, and the daemon and the tooling never do.** The CDN is a registered surface (C79, governed surfaces; `SURFACES.md`), and a page renders whole without the art. *Why:* invariant 1 governs daemon-originated traffic, and a browser's fetch of an image a page names is the browser's, as the authorize navigation is. *Pinned:* nothing yet.
- **C143 — A shared refusal speaks the request's own words, a view's field or a term, never a frontend's flag; an adapter may add its own spelling after them.** `sort` and `count` where the search crate refuses a count beside a sort, so one wording holds on a page, in an MCP result and at a terminal. *Why:* a refusal worded for one frontend reads as a defect on every other, as ids did before C116 (no id in user-facing text). *Pinned:* nothing yet.

## Not doing

What someone would propose and the project declines, each until the trigger it names or for good; the backlog is the repository's GitHub issues.

- A standalone queue TUI (`dash` as its own binary): not until a queue-monitoring slice opens.
- A web listener beyond loopback (a phone on the LAN): not until a design of its own rules its security story.
