## The rule

**History lives in git and in the records. Everything else says what
is and why.**

The boundary is by place, never by line:

- **Current**, swept: `crates/`, `tools/`, `.github/`, the root's
  configuration (`Cargo.toml`, `deny.toml`, `.cargo/`, `.config/`,
  `.githooks/`), `AGENTS.md`, `README.md`, `CONTRIBUTING.md`,
  `SECURITY.md`, `GLOSSARY.md`, `REVIEW-CHECKLIST.md`,
  `TESTING-NOTES.md`, `SURFACES.md` and `.claude/skills/`. The
  generated `CLI-REFERENCE.md` and `MCP-REFERENCE.md` follow their
  sources.
- **Read, never edited**: `decisions/`, whose words are the owner's
  (C170), and the "Where it came back" column of
  `REVIEW-CHECKLIST.md`, whose form is his. Sweep both and bring each
  candidate in the report.
- **Records**, never swept: everything else. That means `HISTORY.md`,
  the ledgers, `roadmap/`, `audits/`, `search/`, `docs/design/` and
  `spikes/`. The step still writes its own records there: a saved
  review, the road.
- **Data and names**, in a current place and outside the sweep: a
  fixture (`*.json`, anything under a `goldens/` directory, a table's
  values), a string literal, an identifier, a file's name. A comment in
  a `.toml`, a script, a workflow, or a `.js`, `.css` or `.html` the
  CLI serves is a comment.

In a current file, a **pointer** stays and a **story** goes:

- **Pointers stay:**
  - a ruling id (C…), an invariant, a ground-truth claim (N…, T…);
  - an issue that is open work;
  - a cited text whose content the claim rests on (`<path>` at `<commit>`);
  - a date that is part of a name (a fixture file's);
  - a working noun and its procedure (a seat, a cold review, a step,
    as `GLOSSARY.md` and the skills use them).
- **Stories go:**
  - a date;
  - a particular step, rung, round, review, seat, sitting or audit;
  - "found by", "the cold review at", "was X until";
  - an issue or a commit cited only as where something came from;
  - a version ledger (a wire schema's `History: v1 …, v2 …`): the
    constant keeps its current number and what that version is.
- **A dated fact about GGG, the trade site or the forum** cites its
  claim (N…, or T… in the trade appendix) instead of its date. If it
  has none, keep it with its date and list it in the report: a new
  claim is the owner's to add.
- **A clause's reason stays.** Where the story carries the reason, the
  reason is kept in words and the story goes.

Examples from `acquisition-plan`:

- "(an untagged enum would lose that: review finding 2026-09-02)" →
  "(an untagged enum would lose that)"
- "the release seat met 5 MB of them" → "listed whole, they reached
  5 MB"
- "(the answer-facts seat, CLI fault 10: the status counted them and
  offered no route)" → "(without it the status counted them and
  offered no route)"

## How

Two sweeps, both under `rg -i`: a `grep -E` that does not know `\b`
drops half the hits and says nothing. The markers:

```
rg -in 'step-|-step|\bstep [0-9]|\brung\b|tracer|PRICING-SLICE|\bround [0-9A-Z]\b|fix round|finding [0-9]|review of|cold review|\bseat\b|20[0-9]{2}-[0-9]{2}-[0-9]{2}|#[0-9]{2,3}\b' <paths> -g '!*.json' -g '!**/goldens/**'
```

The narrative, whose hits are candidates and mostly no history:

```
rg -in 'found by|used to|no longer|sitting of|the owner.s (word|ruling|answer)|\bat `?[0-9a-f]{7,40}\b' <paths> -g '!*.json' -g '!**/goldens/**'
```

Neither finds a story that carries no marker: also read the paragraph
each hit sits in. Subagents may do the reading crate by crate. You
judge every edit and make the commit.

- **Issues.** The open ones are
  `gh issue list --state open --limit 400 --json number --jq '.[].number'`.
  Run it once a batch and hand the list to each reader; a number not on
  it is where something came from.
- **Comments only.** Before each commit this prints nothing, or only a
  code line whose trailing comment changed:
  `git diff -U0 -- '*.rs' | rg '^[+-]' | rg -v '^(\+\+\+|---) ' | rg -v '^[+-]\s*(//|$)'`
- **The measure.** A crate's comment lines, before and after:
  `rg -c '^\s*//' -trust <crate> | awk -F: '{s+=$2} END{print s}'`.
  A batch's size before it starts: the marker sweep's lines, counted.
- **Help text.** A `///` on a clap argument or an MCP parameter is help
  text, and only the cli and mcp crates hold any. The marker sweep over
  the two references prints nothing, so expect no reference and no
  golden to move in any batch. One that moves is read as a diff; one
  that moves for any reason but a help line cut on purpose, named in
  the commit message, stops the batch. Regenerate under
  `ACQ_UPDATE_FIXTURES=1` only for such a line.

## Batches, in series

A batch is, in order: the cut, one commit; `tools/gate.sh` and
`tools/gate.sh --only doc`; one cold review (C175: prose cut across
many files), saved and committed; its fixes, one commit; both gates
again over the tree to be pushed; one push. A push cancels a gate run
in progress, so a batch is pushed once, and only after CI on the push
before it is green. The next batch may be read and edited while CI
runs, never while a local gate runs.

A batch's review is saved as
`roadmap/reviews/cut-293-5-b<batch>-<sha>.md`, and a batch gets at most
three, counted by `ls roadmap/reviews | grep '^cut-293-5-b<batch>-'`.
That is past C176's count for a step, on the owner's word in the
session's prompt, quoted in each commit that saves one. A fix round of
comments alone takes no review unless it cuts across many files (C175).

Each batch's commit messages name this brief, which is how the
reviewer finds it.

1. `acquisition-store`, `-verbs`, `-client`, `-protocol`, `-transport`,
   and the ledgers above `REFRESH_PLAN_SCHEMA`, `LISTING_SCHEMA` and
   `SHOP_SCHEMA` in `acquisition-plan`
2. `acquisition-daemon`
3. `acquisition-cli`, `-mcp`
4. `acquisition-search`
5. `tools/`, `.github/`, the root's configuration and the current
   documents

**A batch is done when** the marker sweep over its paths matches only
what stays, and its cut's message counts that by class (a name in code,
a dated name, an open issue, a claim's evidence, a working noun) and
lists singly what fits no class.

## Stop and ask

- A comment or a document line is the only record of a property: keep
  it and ask.
- A golden or a reference moves beyond a help line cut on purpose.
- A batch's review finds a reason lost with its story.
- A batch's third review still finds faults (C176).
