# t5-r1 — the clock and the door (#141, round 1)

The first round of t5's design (`t5-design.md`, ruled 2026-10-31,
C158). Written from the design's §2 and §4, the spike's code on its
branch (`acquisition@11add49b`, the head of
`worktree-agent-a3d9540486fed65ea`), and the tree at `958f64d9`,
every line printed.

## Goal

When this round is done, the daemon's tests have their door: a
scenario constructs a daemon on a parking clock facing a fixture,
sends requests through the protocol, awaits on the daemon's events,
reads the journal and finishes through the oracles, on a
current-thread runtime the door owns whose park hook moves the clock
only while nothing the scenario started can run (C158). The first
table runs through it, the 429 hold the spike drove, in milliseconds
and with the system clock's journal. Every blocking task the daemon
spawns is counted through one helper, and an arch check pins that.
The stateful mock runs on the daemon's clock everywhere. The login
has an auth-change notification the door awaits. `BlockingClock` is
retired, its one test on the parking clock asserting what it
asserted. No production behaviour changes; no word a user meets
changes; the gate's test time does not grow.
