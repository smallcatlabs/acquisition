- **Findings, most severe first.**

  1. **§2.1, §3 and §4 — The door cannot express the scenarios assigned to it.** `handle_request` returns `Response`, while `submit(Request) -> JobId` cannot represent refusals, auth replies, status, cancellation acknowledgements or logout results (`daemon/server.rs:254`, `:283`, `:352`). Failed code exchanges can finish before any profile job exists (`daemon/tests/login.rs:342`, `:403`), so a job-terminal waiter cannot replace those polls. Priority and account *are* carried by `Request::Submit` (`acquisition-protocol/src/protocol.rs:424`); the incompatibility is admission: reserved submitters and daemon-only kinds are refused (`daemon/queue.rs:1183`, `:1204`), while existing internal-input tests deliberately submit malformed params as `"daemon"` (`daemon/tests/queue.rs:427`, `:491`). **Smallest change:** specify `request(Request) -> Response`, the supported nonterminal/auth waits, and a partition retaining persisted/internal-input component tests outside the frontend door. Preserve subscribe-before-snapshot and re-read behavior: events are hints; finish, cancel and restore do emit (`daemon/dispatch.rs:471`, `daemon/queue.rs:648`, `:349`).

  2. **§4 rounds 1–3 — Retiring ManualClock in round 2 depends on migrations assigned to later rounds.** The parking clock parks; the old clock advances during `sleep`. Existing tests still run ordinary Tokio runtimes, and `wait_terminal` continuously yields (`daemon/tests/harness.rs:582`), preventing the proposed park hook from running even if installed. Refresh tests still need automatic advancement in round 3 (`daemon/tests/refresh.rs:405`). **Smallest change:** retire ManualClock only after every dependent runtime and waiter has migrated, or move that migration into the retirement round. Replacing fifteen files’ clock names or retaining `advance` alone is insufficient.

  3. **§3 and §4 — Two retirement holders preserve less than their retired tests.**
     - **BlockingClock:** its test proves a zero-duration independent job completes while **two different rate waits remain parked** (`daemon/tests/dispatch.rs:192`, `:233`, `:244`). A single-job 429 hold table does not hold that property. Keep the test on the parking clock, with that ordering asserted, before retiring its clock.
     - **responses.rs:** the brief misses both **non-2xx status precedence over failed body transfer** (`daemon/tests/responses.rs:111`) and **syntactically invalid successful JSON** (`:129`). Dispatch’s malformed-listing test uses valid JSON (`daemon/tests/dispatch.rs:376`); its 500 case has a complete body (`:1113`). Retry bounds already have wire holders at dispatch **518** and **553**; terminal Retry-After cases at **595**. Add holders for the missing properties and retain required error evidence, rather than replacing every assertion with a coarse failure kind. The limiter’s truncated-response tests (`ratelimit/tests/spec.rs:1869`, `:2579`) exercise the choke, not `classify_api_body`.

  4. **§2.1 and §3 — `Script(Vec<ScriptedResponse>) | Mock | None` cannot represent the existing server fixtures or the promised new transport twin.** The current response type always writes a complete, correctly sized body (`daemon/tests/harness.rs:236`, `:365`; `mockggg.rs:1058`). Existing scenarios need arrival/release barriers and request-body checks (`daemon/tests/sessions.rs:94`), account-dependent responses (`daemon/tests/harness.rs:1030`), and bearer-dependent responses deliberately independent of an expected sequence (`daemon/tests/bearer.rs:10`). **Smallest change:** admit those fixture capabilities explicitly, including raw/truncated responses, or identify which fixtures remain outside the door. Include construction inputs for rails, initial sessions, persistent world/database and exit bounds; the three drawn arguments do not supply them.

  5. **§3’s failure-kind paragraph and §5 — A protocol change is assigned to a build brief without an explicit owner ruling.** `Outcome::Failure` currently carries error, children and payload, with no classification field (`acquisition-protocol/src/job.rs:150`). Several proposed kinds have already been flattened into `ApiError::Other` (`daemon/kinds.rs:1070`, `:1082`, `:1091`), while halted work is parked rather than terminal (`daemon/dispatch.rs:565`). Adding a kind to `Outcome` changes serialized and persisted answers, including JSON a user meets; it is not confined to whichever frontend elects to read it. **Smallest change:** put the field, vocabulary and backward-read policy before the owner explicitly, or choose a daemon-internal classification surface and remove the promise that it resides in `Outcome`.

  6. **§2.5 — The lower bound at exit.rs:301 cannot remain a real-time assertion after its drain becomes virtual.** That test measures the Tokio drain and installs no OS-thread end hook (`daemon/tests/exit.rs:289`, `:296`, `:309`). Only the other cited test measures the independent bound thread (`:388`, `:400`, `:428`). **Smallest change:** retain the latter real lower bound and convert the former to a logical deadline assertion or its existing expiry holders. Remove the already-retired exit 3 s/5 s ceiling retirements; `roadmap/LEDGER.md:61` records their earlier removal.

  7. **§2.6 and §3 — The off-door inventory is incomplete and contradicts the migration table.** Exit **1098** is the blocked-judge/signal-admission test, not a listener-error test. Exit **1662** serves a fabricated listener with `inner: None`, so it is not a real-socket test (`daemon/tests/exit.rs:1658`). Callback socket tests directly exercising `wait_callback` are missing (`daemon/tests/login.rs:531`, `:561`), as are explicit component exceptions for pure classification, lifecycle tables and fabricated queue/verdict states. Conversely, credentials **318** uses neither `answered`’s blocking receiver nor a real protocol socket; its async held-clear scenario can migrate after replacing its sleep, and §3 already assigns it to the door. **Smallest change:** classify tests by the boundary they require, not their current runtime attribute; distinguish frontend/callback sockets from the GGG sockets every scripted server uses.

  8. **§2.1 — “Oracles always” still leaves a missing-journal escape hatch.** `Server::None` describes absence of a server, not absence of a journal; journaling can write an empty header-only journal (`rails.rs:447`, `:468`). The existing missing-file skip is exactly what must cease to decide whether assertions run (`daemon/tests/harness.rs:694`). **Smallest change:** require a journal for every door scenario, including `None`, fail on a missing file, and run the applicable empty-send oracles. Name intentional journal-disabled component tests separately.

  9. **§2.2–3, §2’s timeout paragraph and §5 — The off-runtime claim exceeds what the proposed count covers.** Besides the two production `spawn_blocking` sites, a literal source-wide guard encounters the test’s direct spawn (`daemon/tests/credentials.rs:255`). Signal and bound threads remain outside that helper (`daemon/start.rs:162`, `daemon.rs:276`); the reaper belongs to the client (`acquisition-client/src/client.rs:2151`). Those persistent threads must not be counted as outstanding scenario work. Also, a silent GGG request retains its send permit throughout connection/body completion, so the hook freezes virtual time beside its real timeout (`ratelimit/choke.rs:1008`, `:1018`), contrary to the timeout paragraph. **Smallest change:** define the count as relevant blocking tasks, scope the guard explicitly, preserve `landings` independently for the idle/drain verdict, and name excluded threads. Narrow the timeout trigger to needing timeout-expiry/race coverage; controlled delayed responses already exist.

  10. **§4.6 and §6 — An unspecified weekly artifact is not a reproducible “no new survivor” baseline.** Weekly runs are four shards on their checkout (`.github/workflows/weekly.yml:35`, `:55`), and exclusions identify exact source locations (`.cargo/mutants.toml:24`, `:36`). An available artifact may predate the input tree; line movement changes identities and exclusions. A run first arranged in round 6 is too late to be a before-run unless it explicitly checks out the original input. **Smallest change:** capture the baseline before round 1, or require an equivalent recorded commit/config/toolchain/tool version and all shards; compare corresponding mutants and classify additions/removals separately. This remains evidence only for the configured limiter/choke/gate scope.

  11. **§5 — The draft ruling is a mechanism-heavy entry whose literal property excludes its own explicit clock moves.** It specifies the runtime, hook and helper, occupies approximately **963 bytes**, and says time moves only when nothing can run despite `door.advance` being called by runnable scenario code. Registry entries are limited to 800 bytes and put mechanisms in code comments (`tools/bothy.py:21`, `:42`). Its universal “daemon’s tests” also conflicts with the retained component tests and C157’s synchronous machine scripts. **Smallest change:** state the scenario boundary and safety property, qualify *automatic* time advancement, preserve explicit moves and component exceptions, and move implementation details to code documentation.

  12. **§3 and §5 — The exempt lists describe different domains, and the proposed alternatives are not exhaustive.** Production’s list governs API-route probes (`daemon/routes.rs:154`); the oracles additionally exclude token traffic sent through another path (`daemon/tests/harness.rs:787`, `acquisition-client/tests/harness/mod.rs:720`). Simple equality therefore compares unlike lists. A standard-library-only data file included by both consumers is another C1-compatible option. **Smallest change:** distinguish API exemptions from the separate token rule and specify that composition in any comparison. Keeping the client’s independent contract list with a check is a reasonable small recommendation under C1; C1 does not make it the only alternative to moving data into the protocol.

  13. **§1 — The census repeatedly presents textual occurrences as executed calls, tests or scenario rows.** Definitions inflate the constructor and teardown counts; multiline formatting hides lock/auth accesses; table rows are confused with constructor occurrences. The concrete corrections are listed above. **Smallest change:** print each measurement’s scope and expression, label occurrence counts honestly, and use actual row counts where the design budgets or retires scenarios.
