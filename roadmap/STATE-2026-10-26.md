## 1. Where the project is

**The core is sound and the product works.** A reader traced every HTTP path: one `reqwest` client, four sends, each inside a permit of the gate, so invariant 1 holds in the code as in the registry. The layering holds: every CLI verb and MCP tool reaches the same functions (search in the search crate, pricing in the planner, the daemon-and-store verbs in the verbs crate), and the web UI renders the verbs' documents with JSON on every route. The journey through the MCP took me from an empty store to a rendered shop page in a few minutes with refusals that named the remedy each time; the `life>70` refusal ("`life` is no field the language knows; `describe fields` lists all 74; near it: level>70, links>70, pseudo.life_regen>70") is the project at its best.

**The governance is sophisticated, coherent, and able to take criticism.** The 2026-10-19 assessment proposed a simpler shape and within a week most of it landed: parks became issues, slice records became the checklist and one-line history, the notes directory went, one budget replaced seven. That is rare.

**The weight is real and it is growing again.** Since the alpha: 372 commits, 270 of them (73%) touching only markdown; 597 KB of commit messages in seven days; the honesty slice spent about 226 KB of briefs, reviews and messages on 7.4k lines of Rust. Tracked markdown is 2.17 MB against 6.57 MB of Rust. The registry's entries sit at the byte limit again (28 of 147 within 50 bytes of 800, up from 38 of 119 a week ago under a smaller registry), and the AGENTS budget sits at 15,235 of 15,277 under a temporary raise. The gate itself is cheap (37 s warm, about 55 s after a leaf edit, 163 s after a store edit, 220 s cold on ten cores); the cost is reading and writing prose, not running checks.

**The user base is one, and the first sustained real use is weeks away.** Phase 3 is the owner running league 3.30. The alpha has no known external user. The seats are the only instrument that measures the agent-facing surface, the last one predates the honesty slice's word changes, and its worlds are gone.

## 2. Patterns under the patterns

**A. The immune system has no apoptosis.** Every fault becomes a named test, a checklist row and, if it recurs, a review shape. Nothing retires: P6 says ceremony is retired by evidence, and in the record I found one retired checker. The review prompt now carries nine shapes plus about fifty checklist rows, Codex finds P2 findings in test-hygiene commits (the tempdir rounds today), and the only stopping rule is the owner saying "no further review". The suite is 58% of the Rust and the gate does not feel it; the reader does. The h3 brief had to list every test asserting on a wording before the wording could change.

**B. The owner's authority runs through words, and the words are the mass.** Rulings come first for every class of change, including the delegated class (C63, a column shows an id; C109, a nesting limit), so a flag change needs an 800-byte entry with Why, Pinned and glosses before the code. The owner's leverage is then spent on wording: `ae837d12` restores a semicolon a session trimmed to fit the limit. The compressed register ("the doors take the world", "a count says what it counts") is memorable in rulings and commit messages and a tax everywhere else. The Fable synthesis counted about thirty undefined working nouns and four meanings of "door". The register leaks into the product: the MCP `search` description is 3,864 bytes in one paragraph; the tool list is 41 KB per session; and C146 ("a count says what it counts") had to be written because four seats stopped on six words.

**C. Mechanisms taken for properties.** Each of these is held by lore or a rule where the root could be fixed:
- C84's build-order rule ("build again after tests") appears in five places. The auditor traced it to feature unification: the all-targets build is a second feature set, so a store comment recompiles nine crates twice. Equalise the feature graph and the rule retires.
- C13 and C88's "the MCP never spawns in real mode" guards a human in the loop, but the human act is the login, and a spawn that restores a session from the keyring is not a login. What the rule produces is the ten-line dance in the README's "Your agent" (`ACQ_IDLE_SHUTDOWN=3600 acq auth check`), and issue #1 waiting for 4-full. The 60-second idle default is the other half: a daemon alive for an hour is not a stray process, and a longer-lived daemon keeps the limiter's history, which is better for the GGG relationship, not worse.
- About twenty rulings say *Pinned: nothing yet*. They are held by discipline, and the field makes them look held.
- "The gate decides" while the Windows gate has been red on every push since `77771530`. The auditor diagnosed both reds as test defects from the assertion order alone: `temp_dir()` reads `TEMP` on Windows, not `TMPDIR`; the c147 pin compares a plain path with a `\\?\` one. A red test step also skips Windows clippy, the only lint of `cfg(windows)` code, so four pushes have gone unlinted.

**D. The daemon has a liveness hole exactly where the owner will stand in phase 3.** Keyring and account-index I/O run under the `shared` lock (`refresh.rs`, `install_tokens_locked` and `persist_credentials_locked`; `login.rs`; logout). `hello` waits behind `shared` (`server.rs:88`), so a keychain prompt makes every client report the daemon unresponsive and C86's "answers hello in milliseconds" is false in that state. C135 is unbuilt, so every lifetime refreshes at first token use, and a macOS ad-hoc-signed build prompts on keychain modify. The owner rebuilds often; the first job after each rebuild meets that dialog. The live-run skill's `sign-acqd.sh` is the workaround; a user has none. The roadmap already names the lock merge under "Open".

**E. One fact in many places, inside the code the reviews never read whole.** The job-kind vocabulary lives in about ten places across three crates (a new kind touches fourteen files, and a kind the store's `from_job` does not know makes `record` return `Ok` silently, a C144 sibling). Five identical `plural` functions, cancel written twice, the default league in five sites, two `serial_key` functions, ruling copies in module docs that have drifted from the registry (`routes.rs:10` names one declared route; C32 names two), and four doc comments citing a `CONTEXT.md` that no longer exists. The 2f scan that would have found these stayed outside the repository.

**F. The generated references pin wrong sentences.** `MCP-REFERENCE.md` and `CLI-REFERENCE.md` are goldens of the binary's own words, so a sentence that is wrong is pinned, not caught. Verified today: the MCP's `submit_job.kind` lists `refresh` (retired under C76; the daemon refuses it by name) and omits `apply`; `describe.names` omits `trade` while the instructions say to send `["trade"]`; `auth logout`'s help lists three keyring values and the code emits a fourth (`failed`); C76 names `--characters` and the CLI has only `--tabs` and `--all` (`plan_cmd.rs:375`); the MCP has no selection plan at all and nothing says so.

## 3. What to protect

The invariants as properties; `arch-check.sh` with its breakers; the journal as the GGG-side contract and its oracles; the ground-truth claims; the fault-shape vocabulary; goldens that name the facts a reader must find; the one `Fault` matched exhaustively by every adapter; one request reader where every printed route runs; `exact.rs`; the web UI as a renderer with JSON on every route; the mock-world rule and the live-run skill; rulings with a Why; the seats; and the habit of writing from the artifact. These are where the record shows the framework paid for itself. None of the proposals below touches them.

## 4. What I would do next, ranked

The calendar is fixed: league 3.30, then `alpha.2`, then PoE2 in December. The honesty slice was a day the plan did not have, and the next "one more group" would be too. I would freeze new slices and spend the time before the league on readiness, then let real use write the next list.

**R1. League readiness, before 3.30.** About a week of agent work and two rulings.
1. Fix the two Windows test defects (#77) so the gate decides again on both platforms, and run clippy and the script checks with `if: !cancelled()` so a red test cannot hide them. A day.
2. Take the credential and index I/O off `shared`, keeping C144's property (the result still reaches the caller; do the I/O outside the lock and publish under it), and answer `hello` ahead of `shared`. One design brief, the one daemon change I would make before the league. Build C135 (#55) with it or after.
3. The daemon's lifetime for agents: the owner's ruling. My proposal is the smaller one, an idle default of an hour with the knob kept (an amendment to C3), paired with evicting finished jobs from memory past retention, since a reader found they are never released and their params held twice. The README's "Your agent" section then loses its dance. The larger one, the MCP spawning in real mode when the keyring holds a session, is a C13 amendment I would bring as a question, not a recommendation.
4. `acq diagnose`: version and contract, platform, the daemon's status document, store counts, rails state, the journal's tail (already secret-free) and the log tail with paths and usernames redacted by one function, pinned by a test that feeds a known secret. The README's "Reporting" section says "paste its output". The first stranger's bug report is then actionable, and the owner's own `RUN-LEDGER.md` rows come from one command.
5. The verified surface defects in section 2F. Half a day; each is a shape the review prompt already names.

**R2. Retire mass by fixing roots.**
1. `tools/gate.sh`: the ten stages, a per-stage exit table, nonzero on any, ending with `cargo build --workspace`. The five copies of the exit-status and build-order lore go, and the class of memory notes about misread gates with them.
2. Measure the feature-graph fix. If the all-targets build can share the plain build's graph, retire C84's build-order rule and the final rebuild: P6 applied for real.
3. Drop the review choreography. Reviews stay under `roadmap/reviews/` for good (docs-check already excludes it); a ledger row is a commit range and a date; no save-alone, delete, cite-whole or hash list. About four markdown-only commits per step disappear.
4. Rulings after, for the delegated class. An agent-facing design decision is recorded in the commit and listed at the close; it is promoted to the registry only when it turns out to be a boundary. The owner's reading drops to boundaries and findings.
5. The AGENTS budget and the 800-byte entry limit become notes, not gate failures; the history-marker refusal does the useful work. A glossary of the thirty working nouns (door, world, seat, sitting, rail, rung, slice, round, tail, fold, route, home, basis, scope, place) in `AGENTS.md` or named from it.

**R3. Measure the agent surface, since it is the stated first goal.**
1. A seat ledger beside `RUN-LEDGER.md`: date, build, door, calls, calls to first correct answer per task, stops, faults by fate. Keep the seat worlds' stores so a rerun reads the same facts.
2. A seat after R1.5 and before `alpha.2`.
3. Trim the MCP surface: tool descriptions under about 600 bytes each with a pointer to `describe`; the language and the long explanations as MCP resources (a shape the protocol has and `rmcp` 3.1 supports; the server exposes tools only today); the `initialize` instructions as a short list. Measure by `tools/list` bytes (41 KB today) and the seat's calls-to-answer. Apply C146's principle to tool descriptions: one plain sentence a reader with no registry can parse, and a test that holds a description to a length.
4. Build the held corpus in `acq-mcp` (GUI-NOTES move 2, ruled 2026-10-19, "the smallest change on the list", still unbuilt). Every agent search drops from about 480 ms to the evaluation alone; it is also the first stone of 4-full's backend.

**R4. Bound the backlog.** Three milestones (3.30 and `alpha.2`, 4-full, PoE2) across the 63 open issues, which carry area and trigger labels and nothing else; ten minutes. A rule for the roadmap's "Open" list: an item older than one phase becomes an issue or a Not-doing line. The items marked "the owner's" get decided or filed.

**R5. Cheap automation around the asset.** Fuzz the `X-Rate-Limit-*` header parser (`ratelimit/policy.rs`, which has no generative test) and the IPC frame decoder; `cargo-mutants` over `ratelimit/` and `gate.rs` on a weekly schedule, since the project already breaks invariants by hand; Dependabot for Actions and Cargo; a weekly scheduled CI run so advisories surface without a push; the macOS keyring round trip exercised somewhere, since `keyring_round_trip_survives_a_fresh_entry` passes locally by returning early and the owner's own platform is checked by nothing; a gate stage that fails when `ACQ_UPDATE_FIXTURES` is set or the tree is dirty after tests (today a shell with it exported, even at `0`, regenerates every fixture and goes green).
