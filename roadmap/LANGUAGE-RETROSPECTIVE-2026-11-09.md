# Acquisition in hindsight: the language, the form, and the agentic developer

A retrospective written 2026-11-09 at `95d715b3`, at the owner's request:
take stock of what the Rust rewrite organically became, and ask what
building it in Go, Zig, C, C++, or another language would have been
like, seen from the seat of the agentic developers who built it. There
is no right answer. The point is to learn what the form taught, and
where the choice of Rust actually landed on the tradeoffs it carried.

This file is uncommitted and the owner's to keep, move or drop. It
makes no ruling. Where it raises something for review, it says so.

## 0. How this was made, and how to read it

Four Opus readers surveyed the tree read-only, one each over the
network core, the data crates, the frontends with the verification
machinery, and the development history including the report series on
`report/agentic-development`. Their findings were folded into one
description of the application as built, with the repository's own
measurements. Six more Opus sessions then each steelmanned one language
against that description and a common set of eight questions: Go, Zig,
C, C++, a garbage-collected typed language of the session's choosing
(it chose F# on .NET 10, with C# and Kotlin as runners-up), and the
language the models know best (it chose TypeScript over Python). Each
was told to be a designer, not a cheerleader, and to mark every claim
about its language's 2026 state that it was not sure of. Fable wrote
this synthesis and holds the judgements in it.

Three caveats bound everything below.

- **The commit record cannot see pre-commit compile loops.** A borrow
  error fixed before a commit leaves no trace. The evidence that Rust
  cost the agents little at the keyboard is therefore indirect: the
  shapes they chose, the faults that recurred, and what the messages
  do and do not mention.
- **The language studies are reasoning, not experiments.** Nobody built
  Acquisition in Go. Their estimates of compile times, binary sizes and
  memory are marked as estimates and should be read as such.
- **Every count here names its source.** Where a number is mine, the
  command is named; where it is a reader's, the file or commit is.

## 1. The form we built

### 1.1 The shape

Ten crates in four layers, 227k lines of Rust of which 58 to 64 percent
is test, 70k lines of markdown, 24k lines of Python and shell, 454
packages in the lockfile, toolchain pinned at 1.99.0, edition 2024. Three
binaries ship side by side: `acq`, `acq-mcp` and `acqd`, the daemon that
is the only process that ever speaks to GGG. The whole design defers to
one asset, the OAuth registration and its rate-limit standing, and the
founding incident is a Cloudflare block the C++ app earned in July 2024
with a thousand HEAD requests in a minute.

The layers, as the readers found them:

- **The protocol** is a serde wire: internally tagged `Request` and
  `Response` enums with unknown fields refused, closed `ErrorKind` and
  `FailureKind` enums, and a contract revision digested at build time
  over the protocol and store sources, the manifests and the lockfile.
  It links serde and nothing else.
- **The daemon** holds jobs, a dispatcher with one task per scheduling
  key, a header-driven limiter with no local token counting, a two-send
  gate whose RAII permit is the completion signal, a `ChokePoint` that
  privately owns the one transport which privately owns the one HTTP
  client, rails (tripwire, send ceiling, a send journal with no token or
  body, a persisted Cloudflare block mark), OAuth with a `Secret`
  newtype that cannot be serialized or dereferenced, single-flight
  refresh with a guard that publishes "abandoned" on drop, a credentials
  lock turned into a type so that a writer outside it does not compile,
  a persisted job mirror, and a time seam in which one `Clock` trait is
  the only source of time and every lifecycle is a pure machine
  `step(state, event) -> effects` driven by a driver.
- **The store** keeps GGG bodies verbatim as JSON values in SQLite with
  the schema internal, lifts items into a table keyed by GGG id, diffs
  on ingest, and keeps intent in a separate per-account file written only
  through a typed door under compare-and-swap with tombstones. The plan
  is an envelope whose only deserializer refuses anything tampered.
- **The search** is a typed query tree, a hand-written parser, a binder
  that keeps parsing independent of any corpus, a four-valued evaluator,
  a total derivation that records every unreadable part of a body as
  `Unread` at the smallest grain, exact decimal arithmetic in integer
  hundred-thousandths, 2.4 MB of embedded reference tables generated by
  Python from pinned sibling clones, and an answer that names its basis.
- **The frontends** are adapters: a verbs crate that alone opens a store,
  picks an account, compiles a plan or connects, a closed `Fault` every
  frontend matches exhaustively, a CLI, an MCP server whose tools return
  the document `--json` prints, and a loopback web UI inside the CLI
  binary.

### 1.2 The framings that carried weight

Taking stock means naming which ideas did the work. These are the ones
every reader found load-bearing, and each is independent of the
language.

- **An invariant is a property, never a mechanism.** Rewritten within
  hours of being first written, and the reason the five invariants have
  survived every refactor.
- **The GGG-side contract surface is the send journal**, and every test
  daemon ends in oracles written from the rules rather than from the
  code. This is what lets the mechanism between the wire and the
  protocol change freely.
- **Facts, intent, derivations, effects**, one authoritative mutation
  path each (C34). A sync can never clobber intent, structurally.
- **The door**: drive the daemon only through the path a frontend uses,
  on a runtime whose park hook advances a fake clock, and fail by name
  when nothing can ever run (C158, C160). Time enters as an event and
  leaves as a request to arm a deadline (C157).
- **Fields, not accessors** (C101), and **the derivation is total**: any
  text is an item, at worst one whose body is unread. These two kept the
  hostile JSON surface honest.
- **The plan is an authorization envelope** that will not parse if
  tampered (C38), and **every answer carries its basis**.
- **Rulings first, findings after**, with agent-facing design delegated
  back to the session on 2026-10-26.
- **The agent is the user**: a seat is a blind model with only the tool's
  own words, and the rulings "no id in user-facing text" (C116) and "a
  count says what it counts" (C146) came from watching one stop.
- **Breakers**: a checker proves it refuses by name, or it proves
  nothing.
- **Goldens that name the facts a reader must find**, so a blind
  regeneration fails (C122).
- **Retire X; held by Y** (C154): a test or check leaves only when
  something that runs is named as its successor.
- **Structure over discipline**: a rule that can be broken silently
  becomes a dependency edge, a lint, a test or a refusal in the binary.
  This is the principle most entangled with the language, and section 5
  returns to it.

### 1.3 What the record says about how it was built

The history reader counted. Of 3,212 commits since 2026-08-01, at most
19 percent mention a language-shaped term (clippy, compile, borrow,
trait, async, tokio, unwrap, panic), and that is an upper bound inflated
by domain words such as a plan that "compiles". Seventy-eight percent
mention a process term (gate, golden, seat, review, brief, ruling).
Forty-eight percent mention words, wording, help, text or the README.
By the reader's own tally over `--name-only`, 47.7 percent of commits
touch only markdown.

The motive for Rust, in the owner's interview: "the fun of learning a
new language, pushing my AI skills, and picking a popular modern tech
stack." No document in the tree argues Rust against Go, Zig, C or C++.
The only stated stack reason is C15's: Tokio and reqwest, "the ecosystem
default." The rewrite-or-evolve record stayed Proposed until the
shipping ruling settled it in other words.

## 2. Where Rust's cost actually landed

The expected cost of Rust is the borrow checker. It did not appear.

- Nine commits in 3,212 mention borrowing; two mention lifetime syntax;
  four mention a rustc error code, three of them in the August spike's
  review rounds. Not one of the four readers found a commit, a module
  doc or a comment recording a fight with ownership, lifetimes, `Send`
  or `Sync`.
- The shapes the agents chose explain why: owned query trees, owned
  items of `Option<String>` fields, `Arc<Self>` receivers, `dyn` seams at
  every boundary, six `Arc`, `Mutex`, `Rc` or `RefCell` occurrences in
  all of store, plan and search. The one place borrowing visibly shaped
  an API is the corpus read, which hands rows to a closure because a
  returned stream would have to own the statement and the transaction it
  borrows. The module doc presents that as a design note.

The cost landed somewhere else: in Cargo as a global resolver, in
compile time, and in tokio's runtime semantics.

**Cargo's feature unification.** A dev-dependency's features (proptest's
`num-traits` with `std`, `getrandom`) unify into the test build, so a
test run wrote a different `acq-mcp` than `cargo build`, and the daemon's
artifact identity (C84) broke. The consequences are all in the tree: a
"build order" hard rule in the entry file, two gate stages (`features`,
`artifacts`), a pin block in the CLI's manifest, tokio's `test-util`
paused clock refused because enabling it would split the graph, and a
hand-built `ParkingClock` with an `on_thread_park` hook in its place.
The 2026-10-26 assessment called the build-order rule lore over a root
cause. Every language study found this cost absent in its language.

**Compile time and disk.** After one touch of the store crate the gate
took 232 s before the t2 trims, 140 s after, and 61 to 63 s once the
owner ruled incremental on; the compile is 607 CPU-seconds of which 433
are test units; the daemon library compiles in 24 s plain and 74 s with
its inline tests (`roadmap/TEST-SHAPE.md` §1, `8b02f38b`, `02935da8`).
The target directory reached 65 GB of macOS split-debuginfo objects in
September (`eabb9087`), 124 GB on 2026-10-25 (`77771530`), and measures
113 GB today by `du -sh target`. A fresh worktree costs 15 GB. Unit tests
moved out of `src/` because the protocol's build digest hashed the
store's sources, tests included (`e9b8c40e`). The suite itself is not
slow: 1,391 tests in 24 to 26 s, 1,059 of them under a tenth of a
second. The bill is compilation, and the test-heavy methodology set the
size of the bill: every test is a compile unit, and the project chose to
have a great many.

This matters more for agentic development than for a human team, for
two reasons. The gate is the agent's heartbeat: it runs after every
change an agent makes, and a minute of wall time is a minute the session
waits with its context open. And in this project's working practice a
long build inside a subagent could outlive the prompt cache's window,
which is why long builds run in sessions. Compile latency is paid in
tokens, indirectly.

**Tokio's runtime semantics, four bugs.** A `select!` dropped a
partially read frame, so the next read began mid-line (`51f79b81`). A
hand-rolled timeout polled its bound under the same cooperative budget
as the future it bounded, so an expired bound stayed Pending forever;
the fix copied what `tokio::time::timeout` does with `unconstrained`
(`68cb9448`). A blocking `lock()` behind a keychain prompt held every
worker, so a 300 ms drain took 6 s (`d705d62b`, then `e4e2b9b7`). A task
panic was caught by tokio, leaving a job Running and a lock poisoned
behind a daemon no stop could reach (`dd3825c8`); the answer was
abort-on-panic with a fault marker naming the job. Every `dyn` seam
hand-boxes its futures because an `async fn` in a trait is not
object-safe. None of these is ownership. All of them are the runtime.

**Smaller, recurring taxes.** serde's lenient defaults: extra fields
beside a unit variant ignored, an internally tagged unit variant reading
past fields despite `deny_unknown_fields` (so every no-field request is
`Subscribe {}`), and `serde_json` sorting object keys unless
`preserve_order` is on, which lost a document's declared order twice
before a struct fixed it. A Windows `dead_code` lint on items whose only
caller is `cfg(unix)` kept the Windows gate red for fourteen pushes
until a `winclippy` stage lint-compiled the MSVC target from macOS with a
stub C compiler, needed because bundled SQLite's build script wants one
(`8922df04`). A new clippy lint on floating stable failed CI on every
push for weeks until the toolchain was pinned (`cfd3dc9c`, `b298afd1`).
Clippy's variant-size bound forced a box (`59fa4a2e`). rmcp's stdio
transport silently dropped lines serde classed as syntax errors,
including well-formed JSON nested past 128 levels, so `acq-mcp` reads
stdin itself (`e8a229be`). rusqlite 0.35 removed u64 columns. Under
edition 2024 `std::env::set_var` is `unsafe`, which pushed
environment-setting tests into their own processes.

## 3. Where Rust paid

**The review checklist has 77 recurring-fault rows and none concerns
memory safety, a data race, a null dereference or a use-after-free.**
About sixty are domain, concurrency-design, honesty and test-hygiene
faults that no language would catch. The floor came free, and the
reviewers' attention went entirely to semantics. The owner says external
reviews "find material issues almost every time"; every one of those
issues was a semantic one.

**Checked arithmetic caught two hostile-input overflows.** An
`expires_in` added unchecked to a `SystemTime`, and `i64::MIN` in a
corrupt store (`8d407ffa`), both became loud panics in tests rather than
silent wraps. Go wraps; C and C++ make it undefined; TypeScript makes it
`NaN`, which the TypeScript study shows would have opened the limiter.

**A handful of compile-time proofs sit exactly on the asset.** The
`ChokePoint` privately owns a `Box<dyn Transport>`; the transport crate
alone links reqwest and only the daemon links it, with `cargo metadata`
read by a check and the compiler refusing an undeclared crate (the
transport-seam commit `24052df0` records staged break attempts, E0432
and E0463, and retires a grep onto what "the compiler holds").
`Secret(String)` has no `Serialize`, `Deref` or `AsRef`, so no log string
can hold a token. `CredentialsHeld<'a>` holds a guard, so a writer
outside the lock has nothing to pass and does not compile. The gate
permit's `Drop` is the completion signal, and the refresh guard's `Drop`
publishes abandonment, so a cancelled future cannot forget either. The
plan's only deserializer is a `TryFrom`. The closed `Fault` is matched
exhaustively by three frontends, so a new cause cannot ship without a
remedy on every surface; the 2026-10-26 assessment lists that match
first among the things to protect.

**Cargo and clippy as a programmable refusal engine.** The dependency
graph is data a shell script reads; a one-line attribute denies `unwrap`
and `expect` per crate (C47, in five crates); clippy lints another
operating system's `cfg` code from one machine; `cargo doc -D warnings`
is a check; nextest gives one process per test with no retries; assets
compile into one binary; serde makes a strict wire cheap to declare.

**The relicense was trivially clean.** C110 forbids deriving from the
C++ tree, which has many authors. Changing language put a translation
barrier between the agents and the old code; nothing could be
transcribed by accident. The C++ study makes the converse point sharply:
a model asked for the Acquisition item view in Qt has almost certainly
seen `acquisition-qt`, and would need a clean-room ruling and a lint to
be kept from reproducing it.

## 4. Six languages, one question each

Each study ended on the axis its verdict turned on. Those axes are the
most useful thing the studies produced, so they lead.

| Language | Verdict against Rust, for this application built this way | The axis it turned on |
| --- | --- | --- |
| Go | A defensible equal; better had the Windows and compile pain arrived earlier | Is the scarce resource the reviewer's attention per change, or the agent's loop time per change? |
| F# on .NET 10 | Equal on the product, slightly worse overall | Agent fluency against ecosystem friction |
| TypeScript | Worse, though not widely, and better on the inner loop | Can the guard on the GGG relationship be structural, or must it be disciplined? |
| C | Worse, but closer than expected, and better in the daemon core | Who pays for an error the agent did not notice? |
| C++ | Worse, though not by as much as folklore says | Where feedback reaches an unsupervised agent: compile time, or sanitizer coverage |
| Zig | Worse | Agent fluency times language stability |

### Go

The `internal/` rule makes "nothing links the daemon" and "only the
daemon links transport" compiler-held, and the duplicated `FrameReader`
becomes one package. `testing/synctest`, which the study believes went
GA in Go 1.25, is the parking clock and the stuck verdict for free: time
advances only when every goroutine in the bubble is durably blocked, and
a bubble with nothing pending fails with a deadlock report. Three of the
four tokio bugs are absent by the runtime's nature: no cooperative
budget, a blocking syscall detaches its thread within microseconds, and
an unrecovered panic kills the process. The gate would run in 30 to 45 s
without the race detector, with a build cache in single-digit gigabytes
shared across worktrees, and the lockfile would hold 30 to 50 modules.

What Go gives up is on the data side, in exactly the places the
checklist already records. `encoding/json` v1 is more lenient than serde:
case-insensitive field names, duplicate keys last-wins, invalid UTF-8
replaced, and `DisallowUnknownFields` lost silently inside a nested
`UnmarshalJSON`; the strict v2 sits behind a `GOEXPERIMENT` flag whose
GA status the study could not confirm. Numbers in untyped trees are
`float64` unless every decoder says otherwise. Overflow wraps. A zero
value `RefreshPlan{}` is always constructible, so "a tampered envelope
will not parse" holds and "every plan was parsed" does not. `net/http`
is the standard library, so the one-transport rule becomes a typed
analyzer, and two Go-specific hazards sit under invariants 1 and 4: the
transport's hidden retry of an idempotent request on a reused connection
is a second wire send under one journal entry, and any request that
escapes the choke point carries `Go-http-client/1.1` as its user-agent.
The `synctest` door would have to run over an in-memory pipe, not the
real socket, which the owner would have to rule is still the door.

The study's unexpected finding: Go's weaker type system might yield
*more* enforced structure for this owner's rules, because most rulings
are about who may call what, and Go's `go/analysis` framework turns
those into typed checks with breakers (`analysistest`'s `// want` files)
built in, where the Rust tree holds several by grep or by review.

### F# on .NET 10, with C# and Kotlin as runners-up

Chosen because it is the only garbage-collected candidate with real
closed sum types that also sits on a base library covering the operating
system edges on all three platforms: an HTTP client with redirects off,
Unix sockets, named pipes created with a DACL, strict JSON with a depth
limit and unknown-member refusal, a first-party `TimeProvider` with a
fake, bundled SQLite, and an official MCP SDK. Native AOT gives three
self-contained binaries, the same release shape. Discriminated unions
with private representations and signature files give most of what Rust
gets from private fields, `TryFrom` and exhaustive `match`, and
`decimal` with units of measure would make adding two currencies without
conversion a compile error. Hand-written decoders over `Utf8JsonReader`
would remove all three serde-lenience traps by construction.

What it loses: the lifetime proof (no analogue), `Drop` on scope (a
callback API instead), a streamed corpus read that the GC lets escape
its transaction at runtime where the borrow checker forbade it, no
mutation testing for F#, no Roslyn analyzers, a naive held corpus at
300 to 450 MB in UTF-16 strings, a hand-built keyring, and above all a
training corpus perhaps an order of magnitude thinner than Rust's. C#
lost on the absence of closed sum types; Kotlin won on structured
concurrency and lost on the release (JVM startup, GraalVM, JNA for
pipes).

Its unexpected finding, shared with Zig: **one TLS stack becomes three.**
The Rust tree builds reqwest with `rustls-tls` and no default features
(`crates/acquisition-transport/Cargo.toml`), so every OS presents the
same ClientHello. .NET would present SChannel, Apple's stack and OpenSSL
under one user-agent. Section 5 returns to this.

### TypeScript on Node 24

The language the models know best, picked over Python for closed unions
with exhaustiveness lints, the reference MCP SDK, V8's speed and
single-executable builds. The inner loop would be 5 to 15 s against
Rust's 61 to 140 s; the full gate about the same, because type-aware
linting replaces compilation as the long pole. `node_modules` is half a
gigabyte per worktree against 15. Custom ESLint rules with `RuleTester`
`invalid:` cases are breakers in the project's own sense, natively. An
unhandled rejection crashes the process, which is abort-on-panic for
free. Cancel-safety and the budget mostly vanish.

What it loses lands on the daemon. `fetch` is a global, so invariant 1
is held by lint, by a runtime refusal (delete the global, install a
dispatcher that refuses requests without the choke point's private
symbol), and by the journal tests, not by anything that fails to
compile. A synchronous keychain prompt blocks the only thread. There is
no user-only DACL on a named pipe through `node:net`. The held corpus
would be 3 to 7 times larger as V8 objects. Each single-executable build
is 90 to 120 MB and needs JIT entitlements to sign on macOS; three of
them argue for one busybox binary. The lockfile would hold 500 to 900
packages, on the machine that holds the refresh token, in the ecosystem
where self-propagating token-stealing worms actually ran in 2025.

Its sharpest finding is arithmetic. `Number("")` is 0 and
`parseInt("x")` is `NaN`, and `now < nextSafe` with a `NaN` on the right
is false, so a hostile header does not crash the limiter; it opens it.
Rust's checked arithmetic turned the same class of input into a test
panic. And its sober one: the fluency TypeScript buys was already mostly
available in Rust for these developers. The evidence refutes "Rust is
hard for agents" and supports "Rust's build is expensive for agents."

### C

The study took C seriously as the language of SQLite and curl, whose
test discipline is the nearest existing analogue to this project's gate,
breakers and oracles, and it found C better than Rust in the daemon
core. `nm -u` over unoptimised object files makes every edge a linker
fact with no spelling to miss: only the transport references `curl_*`,
only one object references the production constructor, only the store
references `sqlite3_*`, no frontend object references the store's
opener, only one object references a clock. That holds the one-door
rule, the sole-caller rule and the timer rule more strongly than the
Rust tree does today, where the first is a grep, the second is "held by
review and no check", and the checklist carries a row for a source
reader that matched one spelling. The project's lifecycles are already
`step(state, event) -> effects`; in C the loop is the driver, and the
fake clock and "nothing can ever run" fall out of owning it. The
reference tables compile to C arrays, so a table that fails to parse
cannot exist at runtime. Debug C runs two to five times slower than
release where debug Rust runs ten to fifty, so tests on real corpora stay
fast. The lockfile is nine to eleven vendored libraries, and API drift
is near nil.

What it loses is the hostile-input surface and the credential's safety
in memory. Signed overflow is undefined; a GGG string with an embedded
NUL truncates in `strcmp`; PCRE2 backtracks where the regex crate is
linear-time; a curl or keyring completion can arrive for a connection
already freed; a secret can survive a `realloc`. The gate would add
address, undefined-behaviour and thread sanitizer trees, allocation
torture in curl's style, and fuzz-corpus replay on every hostile parser,
and would still reach the Rust floor only probabilistically. Linear
flows such as OAuth become seven-state machines at two to three times the
lines. Had Acquisition been only `acqd`, the study would call C equal or
better; with search, a hostile-JSON derivation and an MCP server, built
by unsupervised agents for hours, it is worse.

### C++

Passkeys with `friend` would hold the one-door rule and "the choke point
is the sole caller of the production constructor" at compile time with
no link edge, which Rust holds by grep and by review. Clang's
thread-safety analysis generalises the credentials-lock proof to every
annotated lock. Asio's timers are templated on a clock, so virtual time
is a supported seam of about eighty lines and no feature graph to fight.
RAII is at parity with `Drop`. Win32 is first-class. CTest is nextest.

What it loses: signed overflow as undefined behaviour, a `string_view`
into a freed query tree, a lock held across `co_await` resumed on another
thread, capturing-lambda coroutines, `detached` swallowing exceptions,
ODR violations across targets, static initialisation order, three
compilers with three dialects, vcpkg's single include directory leaking
every header to every target, and compile times as bad as Rust's for
header edits with no incremental compiler to soften them. The study
predicts ten to twenty new checklist rows under a heading the owner, who
reviews boundaries rather than code, could not audit himself. And the Qt
pull: the most mature native toolkit is the old app's home, its proxy
models are the second semantics C46 forbids, and the C110 barrier
disappears.

### Zig

The build graph is code, so the dependency table can be a comptime array
from which modules are wired and any other edge refused by name at
configure time. `std.json` refuses unknown fields and preserves key
order by default. Tagged unions switch exhaustively, and a comptime loop
can refuse a `Fault` variant with no remedy. Cross-compiling five targets
from one Mac is best in class. An arena per corpus basis frees in one
call and returns pages to the OS. Panic is abort by default. The
lockfile would hold two to six packages.

What it loses sits on the invariants. Zig has no private struct fields,
so the choke point's transport is a file-scope singleton or an opaque
handle. Standard-library networking is importable from every module, so
invariant 1 falls to a grep. There are no lifetimes, so the lock proof
has no analogue and a `defer` forgotten at one acquisition site deadlocks
the gate at two. Lazy analysis never type-checks a function nothing
references. Async was removed in 0.11 and the `std.Io` redesign's
maturity in 2026 is uncertain. The training corpus spans incompatible
versions, so a model writes stale APIs confidently; the first compile of
most sessions would be API archaeology. The words would be larger: a
rename crib, an ownership contract on every slice-returning function
(in Rust the signature is the contract), and a ruling for every grep that
structure held before.

## 5. The tradeoffs in hindsight

These are the ones the evidence supports and that I would not have
predicted at the start.

**1. The borrow checker's cost was paid in training, not at the
keyboard.** A human learns ownership by fighting it. The models had
already seen the fights and chose, from the first commit, the shapes that
pass: owned trees, owned items, shared ownership almost nowhere. The
project's one visible borrowing artifact is a closure-shaped read. The
TypeScript study put the consequence best: the fluency a dynamic language
buys was already mostly available in Rust for these developers. What was
not available was a fast build.

**2. The cost landed in Cargo as a global resolver and in compile time,
and those are addressable inside Rust.** Feature unification cost a hard
rule, two gate stages, a pin block, a refused tokio feature and a
hand-built clock; compile time cost profile rulings, relocated tests and
124 GB of disk. Every alternative language removes these. But Rust also
offers remedies the project has partly taken (incremental on, dependency
optimisation, tests out of `src/`, the one-binary-per-crate layout) and
partly not (a release profile, fewer test compile units). The language
did not force the bill; the test-heavy methodology set its size, and
Rust charged a high rate per unit.

**3. The type system was used where a ruling demanded it, not by
default.** The job kind is a string matched in about seven places
(issue #100, deferred since 2026-10-19). `Life::step` ends in a wildcard
arm. Ids are plain strings. The daemon does not carry the unwrap lint and
has 157 `unwrap` or `expect` calls in production code, 112 of them
`lock().unwrap()`, coherent with abort-on-panic. The strongest structural
holds in the tree (every timer through the clock, one `spawn_blocking`,
one door, probe exemptions) are greps over source text and metadata, not
types. Rust's gift to this project was less the type system's
expressiveness than Cargo, clippy and rustc as a programmable refusal
engine that the agents could point at a rule. The Go study's framing
sharpens it: most of the owner's rulings are about who may call what,
which is a lint shape, not a type shape, and the Rust tree holds those
with the weakest instrument it has.

**4. For a stateless worker, a language's value is the latency and
legibility of its refusals.** The C and C++ studies both turned on this.
A rustc error arrives on every build, names the site and often the fix,
and the agent repairs it in the same turn. A sanitizer report arrives
only on a covered path; undefined behaviour arrives in a seat as a
garbled answer or an hour later as a segfault in an unrelated callback.
The owner, who rules on boundaries and does not read C++, could not
audit the new checklist section himself. The compiler is also the
agent's working memory: change `Fault` and the compiler enumerates every
site to fix, where a dynamic language leaves the agent to grep and
remember. The owner's "dumb zone", the agent reading so much it loses
track, is exactly the condition a static type system relieves.

**5. Fluency sits at the wrong bottleneck, and erased types weaken the
principle the project found essential.** The models are most fluent in
TypeScript and Python, and those languages have the fastest inner loop.
But the record's bottleneck was verification, review and words, not
drafting; and "structure over discipline" exists because the workers
forget, which is the condition under which runtime-erased types hurt
most. The most AI-fluent languages are the weakest for the agentic
principle.

**6. Every property the compiler holds is a page nobody has to write.**
The studies that moved structure into prose (Zig, C++, TypeScript) all
predicted the markdown share would grow: a rename crib, an ownership
contract per function, a ruling with a Why and a Pinned line for every
grep that replaced a type. The one that moved structure into the linker
(C) predicted it would shrink. "The words are the mass" is a property of
governing stateless workers by text, and every study agreed the mass is
language-independent in kind; but the language sets the size of the part
of it that exists only because the compiler would not hold a rule. Rust
subtracted from the words. Cargo's feature graph added a rule in five
places. The net was favourable.

**7. The friction was tokio, not Rust, and the design had already
become C-shaped.** All four recorded concurrency bugs are runtime
semantics: cancellation as drop, a cooperative budget, a blocked worker,
a swallowed task panic. Go's model avoids three of them by nature. And
the project's answer to testable time was to make every lifecycle a pure
machine driven by a driver, which is the shape an event-loop programmer
writes by hand. Async bought the most in linear flows (OAuth, refresh)
and cost the most in runtime rules nobody can see in a signature. The
tokio bugs were each found, fixed and pinned within a day or two, which
is cheap against any alternative; but a project starting again might
weigh a single-threaded daemon loop against the runtime, knowing that it
would end up writing the machines anyway.

**8. Checked arithmetic was worth more than it looks.** Two hostile-
input overflows became test panics. In Go they wrap, in C and C++ they
are undefined, in TypeScript they are `NaN`, and `NaN` on the right of
the limiter's comparison opens the gate. That is a language default
landing on the asset.

**9. The TLS fingerprint is part of the registration's continuity.**
Nobody choosing a language would weigh it, and two studies raised it
independently. The transport links reqwest with `rustls-tls` and no
default features, so every live run since August has presented rustls's
ClientHello under the continuous user-agent. Zig's standard-library TLS
would present one almost no other client sends; .NET would present three
different stacks across three OSes; Go's would be the ubiquitous
`crypto/tls`. GGG's Cloudflare rules are opaque even to GGG support, and
the project's one incident is a Cloudflare block, so whether any change
is harmless cannot be known before a live run. The ground truth carries
no claim about the TLS stack today. **Raised for review**: whether the
TLS stack belongs beside the user-agent in the spirit of invariant 4,
as a numbered claim in `docs/design/network-ground-truth.md`.

**10. Rust absorbed a whole class of review in the cheapest place.** The
owner does not trust an agent that says it is done because external
reviews find material issues almost every time. Every issue they found
was semantic. In C++ the memory and lifetime class returns to an already
overloaded review loop, in Go part of it (races, nil, zero values) does,
and the owner would be asked to rule on faults he cannot read.

**11. Performance from Rust was not automatic.** The held corpus is
about 9.5 KB an item (`search/MEASUREMENTS.md`, M7), 195 to 214 MB for
22,000 items, which the GUI notes extrapolate to about 9.5 GB at a
million. The C++ app budgets a million items in about 300 MB of keys. The
agents designed for correctness and testability, every string owned,
because no ruling asked for compactness. Rust permits an arena, interning
and a columnar layout; C and Zig would have pushed the designer toward
them earlier; a garbage-collected language would have forced the
question sooner at this scale. The million-item case is a corpus-layout
decision in any language, and it is still open.

**12. Changing language was part of the licence defence.** C110 was
trivially kept because nothing could be transcribed. Staying in C++
would have made the clean room a constant review burden, and Qt's
gravity would have pulled a second semantics into the frontend.

## 6. What I would carry forward, knowing this

None of these is a ruling. Each is raised for the owner's review, and
each is something the evidence above points at rather than a preference.

- **The job kind is the project's largest unused sum type.** A typed
  `JobKind` would move the one vocabulary matched in seven places into
  the compiler, where `Fault` already lives. The debt is recorded as
  issue #100.
- **The spelling-sensitive greps are the weakest structural holds.**
  Checks 7, 10, 12 and 14 and the one-door grep lex Rust source by
  pattern, and one has already missed a renamed import. A typed lint over
  the compiler's own tree is the Rust-native answer; `dylint` is the
  usual vehicle and its maturity should be checked before anyone leans
  on it. The Go and C studies both show what the stronger instrument
  looks like: a check on the object, not the spelling.
- **The daemon could carry the unwrap lint.** With abort-on-panic ruled
  (C134), a `lock().unwrap()` is coherent, but a single helper that
  names the abort would let the daemon join the five crates that deny
  `unwrap`, and the remaining 45 sites would each have to say why.
- **Key order could be held by the dependency rather than the
  checklist.** `serde_json`'s `preserve_order` feature at the workspace
  level would retire the "document built through a `Value` lost its
  order" row by construction, if the gate's `features` stage agrees it
  splits nothing.
- **A release profile has never been tuned.** Link-time optimisation,
  one codegen unit, stripping and `panic = "abort"` are each a line, and
  the daemon hashes its own executable at start. Worth a measurement
  before the GUI phase adds a webview.
- **The million-item corpus is a layout decision, not a view
  decision.** `roadmap/GUI-NOTES.md` §6.3 already says so. Interning and
  an arena per basis are the shape every systems-language study reached
  for; deciding whether a million items is a goal belongs before phase 4
  promises a dense table.
- **The TLS stack** is §5.9's raised item.
- **For phase 4**, the studies agree with the ruling already made: the
  loopback web UI is language-neutral, a page in TypeScript over the Rust
  backend is exactly what C46 permits, and if a native shell is wanted
  later, Tauri's Rust backend is the natural home.

## 7. Verdict

Rust was the right choice for Acquisition as it was built, by these
developers, under this owner. It was right for reasons other than the
ones usually given, and by a narrower margin on iteration cost than the
folklore suggests.

The usual argument for Rust is that it is hard but safe. The record says
it was not hard for the agents, and that the safety it gave was less the
borrow checker than a floor nobody had to defend, a strict wire that was
cheap to declare, checked arithmetic that landed on the asset, a handful
of compile-time proofs at the choke point and the credential, and a build
tool whose every fact a script could read and refuse. The project's
central principle, structure over discipline, was built out of those
levers, and each alternative language would have moved some of them into
prose, where this project's mass already is.

The usual argument against Rust is the compiler's strictness. The record
says the cost was Cargo and compile time: a hundred gigabytes of disk,
two gate stages and a hard rule for a feature graph, a minute or two per
gate run as the agent's heartbeat. Those are real, they were paid every
day, and they are the reason Go is a defensible equal rather than a
clear loser. The decision between Rust and Go turns on which fault the
owner most fears getting wrong: a network one, where Go's `internal/`
packages and analyzers hold the boundary about as well, or a
data-integrity one against hostile bodies, where Rust holds more by
construction. For an owner whose founding incident was a Cloudflare
block and whose next phase is a GUI over a hostile JSON corpus, that is
close, and Rust's answer to the data side is the one that lets the
reviewer keep reading only semantics.

What the form taught, beyond the language: the invariants as properties,
the journal as the contract, the door, the seat, the breakers, the
goldens that name facts, and retire-by-naming-the-holder would carry to
any language unchanged, and they are where the quality came from. The
language set the floor the process stood on and the size of the part of
the words that only exists because a compiler would not hold a rule.
Rust set both well.
