# `acq-mcp` — tool reference

Generated by `crates/acquisition-mcp/tests/mcp_reference.rs` from the server's own `initialize` instructions and `tools/list`; a golden file the test keeps equal to the binary. Do not edit: change the tool's attributes in `crates/acquisition-mcp/src/main.rs` and regenerate with `ACQ_UPDATE_FIXTURES=1 cargo test -p acquisition-mcp --test main mcp_reference`. The CLI's verbs are `CLI-REFERENCE.md`.

## Instructions (sent at `initialize`)

Acquisition (provider: mock). Items: search answers a query over every item the store holds — the total, then rows or tables, then counts for each term — describe prints its query language, and show is one item whole. Their arguments and answers are JSON; a count a next step hangs on — what is undecided, what a key could not place — holds the request that returns its members, sent back as printed, view.routes asks every count's, and a refusal is a result marked isError with readings and offers to go on from. A call nested deeper than 127 JSON levels is not read: it is refused as arguments. Begin with search with no arguments, for what the store holds, or with scope.realm named where the store holds several realms (a PoE2 character beside the PoE1 stashes), since a search over several realms is refused and its offers are the request in each realm: send one back. Then describe with names ["fields"], for what a query may ask: describe whole is over 100 KB. A trade site search — its URL, id or query JSON — is the query {"trade": …}, translated to the text a person would type. No tool says what an item is worth: a price is the owner's own listing. Pricing: price_status counts a league's listing state, price_list names the priced items and price_show is one target, each with its price by hand and in game; price_set and price_clear write one hand row (intent only, sending nothing), and over a row the target already has they name the revision they replace; shop_render renders the forum pages for a person to paste, posting nothing; reference_currency is the currency table a price cites. The store tools (search, show, accounts, tabs, characters, store_status, item_events) and the pricing tools read the shared SQLite store directly — no daemon, no network. The refresh slice: sync_policy / set_sync_policy declare intent (local, sends nothing; replacing a policy must name the revision it replaces), refresh_plan compiles it offline into the explicit bounded action set for review, and apply_plan spends exactly that plan as one parent job. Job tools talk to the local daemon; API requests are jobs (submit_job returns an id; poll job_status, then job_result). Rate-limit holds can reach ~5 minutes — a waiting job is the limiter working. Login is done by the human via the `acq` CLI; this server never spawns or replaces a daemon in real-GGG mode — there it submits, applies and quotes only through one a human already started.

## Tools

### `accounts`

Accounts this machine has logged into (from the store's non-secret index; no daemon), each with its store file.

No arguments.

### `apply_plan`

Execute a reviewed plan: its actions and nothing else, as one `apply` parent job the daemon admits or refuses whole at submit (single-request vocabulary + the max_requests budget). Refused offline — before any daemon contact — if the stored sync-policy revision moved since the plan (replan with refresh_plan). In real-GGG mode the daemon must already be running (a human starts it; this server never spawns one there). An empty plan is a no-op with no daemon contact (`applied: false`, `note`, `skipped`). A plan spends each request once: an action whose target was fetched after the plan was compiled, or whose request the daemon already holds, is listed in `spent` (with `fetched_at`, or the `job_id` holding it) and not sent again, so replaying a plan answers `applied: false`, sends nothing, and gives `remaining_requests`, what a plan compiled now would fetch (null while a queued request has not landed). Returns the parent `job_id`, its `account`, the `requests` sent, `spent` and `skipped`; poll job_status, then job_result.

- `account` (string | null)
- `max_requests` (integer | null) — Refuse at admission — before any child job exists — if the plan authorizes more logical requests than this.
- `plan` (object, required) — The plan envelope exactly as refresh_plan returned it (the `plan` field). Re-validated here; a tampered or hand-built envelope will not parse.

### `cancel_job`

Cancel a waiting or running job; cascades to its descendants.

- `id` (integer, required) — The job id, as returned by submit_job.

### `characters`

Characters known to the store, with class, level, league, and two counts — `item_count`, the live items the store holds at the character now, and `fetched_items`, what the last full fetch's body carried (equipment + inventory, socketed gems not counted), null until one — (no daemon, no network). Fresh data is a `characters` or `character` job.

- `account` (string | null)
- `league` (string | null) — Restrict to one league; omitted lists every league.
- `realm` (string | null) — Restrict to one realm (pc, xbox, sony, poe2); omitted lists every realm.

### `daemon_status`

The daemon running: its identity — contract revision, the executable it runs from and its hash (artifact), the world it serves (its canonical store root), the socket it was reached on (derived from the world), how that file relates to the acqd beside this server (artifact_relation: same_file, same_bytes for another copy, different, unhashable, no_sibling, unreported), which of the four dimensions match (contract_matches, artifact_matches, provider_matches, world_matches), and under wanted this server's own version, contract, provider and world with that sibling — all from the one look that judged the daemon; and, when compatible, its vitals: provider, uptime, idle_shutdown_seconds (the idle exit it was started with), connections, queue counts, rate-limit policies learned, rails state (with the journal path), keyring health, and log — the log file the daemon opened, as it reports it. Observes only: running=false when no daemon is up, with persisted — what the ledger on disk holds: waiting, recorded_running, written_at; null when this shell's world has no queue yet — and log, the last daemon's log file in this world when one exists; running=true, compatible=false for a daemon of another contract, artifact, provider or world, reported by its identity alone and never replaced by this server; running=true, responsive=false (with socket and lock_holder, the pid the world's lock records) for something that accepted the connection and did not answer hello within 5s — a wedged daemon, for a human to stop by hand.

No arguments.

### `describe`

The query language `search` takes, as this build knows it (no store read): fields, what a line has, operators, closed value sets, slots, the computed values with their definitions, what a count takes, what a trade site search's clauses become, what is not built and the limits stated — or only the entries named. The whole is over 100 KB, most of it under `computed`: name what is needed instead. The sections are fields (some 20 KB), line, linked, values, composition, operators, slots, counts and explain (each under 4 KB), trade (some 20 KB) and computed; a single name — league, total_res — returns its own entry. A name it does not know is refused, and the refusal lists every name it knows.

- `names` (array | null) — Only these entries: a section — `fields`, `line`, `linked`, `values`, `composition`, `operators`, `slots`, `computed`, `counts`, `explain` — or a name within one: `league`, `total_res`. Omitted: the whole language.

### `item_events`

Item events (added/moved/changed/removed) from recent ingests, newest first (no daemon, no network); `hours` how far back, `limit` how many of the newest.

- `account` (string | null)
- `hours` (number | null) — How far back to look (default 24 hours).
- `limit` (integer | null) — Maximum rows (default 200).

### `job_result`

A finished job's outcome — payload or error — with its job_id and account beside it; answered across daemon restarts (the queue persists), and with no daemon running read from the ledger on disk, where a finished job's outcome is final (an unfinished one is refused as wrong_state with next). A parent's failure carries its children's tally as `children` (done, failed, cancelled, failed_ids), and the first ten failed children with their kind, target and error as `failed_children`. Payloads can be large — prefer the store tools for reading data.

- `id` (integer, required) — The job id, as returned by submit_job.

### `job_status`

One job's state, ETA, and retries. A waiting job with a large ETA is the rate limiter holding, not a hang (holds can reach ~5 minutes). Observes only: with no daemon running it answers from the ledger on disk — running: false, persisted: the job's row as the last daemon recorded it, and next, the command a person runs to start a daemon; a job the ledger does not hold is refused as unknown_job with next.

- `id` (integer, required) — The job id, as returned by submit_job.

### `list_jobs`

Jobs the daemon knows about this lifetime, with states and ETAs. Observes only: with no daemon running it never spawns one and answers from the ledger on disk instead — running: false, persisted: the non-terminal rows as the last daemon left them (jobs, without ETAs) and written_at, how old that picture is; persisted is null when this shell's world has no queue yet. A job command from the CLI spawns a successor that restores them.

No arguments.

### `price_clear`

Remove one target's own price row; what it covered falls back to the next row up, or to the game's price. Intent only: it sends nothing. Stricter than `acq price clear`: `if_revision` must name the revision of the row it removes, and without it the clear is refused naming the current revision (or saying the target has no row of its own) — `kind: "conflict"`, the revision in `revision` — read the target with price_show first. A clear takes a revision too, so the next write's revision continues from it. Returns the receipt: `target`, `written` null, `prior` (the row removed); price_set with the prior's value puts it back. The document `acq price clear --json` prints.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `if_revision` (integer | null) — The revision of the target's own row this clear removes, as for price_set. Required: a clear without it is refused naming the current revision.
- `target` (string, required) — The address, as for price_set.

### `price_list`

The items of one league that are priced, each with both sides of its listing (no daemon, no network): `items`, each with its `subject` (an item address in `subject.target`), the hand row that applies (`manual`: the value, the row's own target in `from`, `inherited`, its `revision`), the game's reading (`game`: the note and the tab name verbatim beside what each reads as, the tab and whether it is public), the `relation` and the `effective` price; `containers`, the tabs, substashes and characters those items sit under, each with its own listing; `items_on_record`, how many items the league holds, so an empty answer says which nothing; `total`, how many the selection holds, and `listed`, how many `items` lists — fewer only under `limit`, the first in listing order, `containers` then being theirs alone. With neither `relation` nor `effective`, items nothing prices are left out, except unresolved ones, which are always listed. A container the facts do not hold is refused (`kind: "not_found"`), never an empty selection. The document `acq price list --json` prints; a refusal is a result marked isError holding `error`, whose words name the CLI's flags (--league is `league`, --in is `in`).

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `covered_by` (string | null) — Only items a row on this target would cover: a folder's tabs' items, a map or unique tab's substashes' items too.
- `effective` (string | null) — Only items whose price this side decides: game, manual, none or unresolved.
- `in` (string | null) — Only items physically in this container: a tab, substash or character address.
- `league` (string | null) — The league; omitted, the league of the container `in` or `covered_by` names, else Standard.
- `limit` (integer | null) — List at most this many items, the first in listing order (some 1.3 KB an item); `total` says how many the selection holds.
- `realm` (string | null) — pc (the default), xbox, sony or poe2; a tab or substash address given to `in` or `covered_by` carries its own.
- `relation` (string | null) — Only items in this relation: none, manual_only, game_only, agree or conflict.

### `price_set`

Set one target's price by hand: one row on an item, tab, substash or character, which what it covers inherits (a tab's items, a folder's tabs, a parent tab's substashes, a character's items) unless a row nearer the item says otherwise. Intent only: it sends nothing and changes nothing in game. Stricter than `acq price set`: a target that already has a row of its own is replaced only when `if_revision` names that row's revision, and without it the write is refused naming the current revision — `kind: "conflict"`, the revision in `revision`, as for a stale one — read the target with price_show first; with no row, omit `if_revision` to create one. A clear takes a revision too, so the next write's revision continues from it. Returns the receipt: `target`, `written` (the row now, with its revision), `prior` (the row replaced, or null after a create) — the undo after a create is price_clear with `if_revision` the written revision, and after a replace price_set with the prior's value and `if_revision` the written revision, unless the prior is a value this build cannot read (a newer build's, replaced only by naming its revision), which it cannot write back — and `in_facts`, false for a target the facts do not hold (not fetched yet, or a typo: the row stands). The document `acq price set --json` prints.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `amount` (string | null) — For exact and negotiable: a decimal of up to four places (`12.5`), or a `wanted/lot` ratio (`1/5`), as a string.
- `currency` (string | null) — For exact and negotiable: a tag of reference_currency.
- `if_revision` (integer | null) — The revision of the target's own row this write replaces: price_show's `listing.manual.revision`, when `listing.manual.from` is the target itself, or the revision a refusal names. Required when the target has a row of its own; omit it only to create one.
- `target` (string, required) — One address: `item/<id>`, `character/<id>`, `tab/<realm>/<id>` or `substash/<realm>/<parent>/<id>`. An answer holds a target as an object, `{scope, realm, parent, id}`: the address is its parts in that order joined by `/`, the absent ones left out.
- `type` (string, required) — exact, negotiable, no_price or skip (the game's `price`, `b/o` and `~skip` work too).

### `price_show`

One target's listing (no daemon, no network): `listing`, both sides with their causes — the hand row that applies with its `revision` and the target it is on (`manual.from`; the target's own row when that is the target itself, a container's when `inherited`), the note and the tab name verbatim beside what each reads as — the relation, the effective price and why; `container`, the one an item sits in; for a tab, substash or character, `items_here` (physically in it) and `items_covered_below` (covered through its children). A bare id is refused with its two readings, `item/<id>` and `character/<id>`; a target the facts do not hold is refused (`kind: "not_found"`) naming the league that holds it, if any, and saying so when it has a row of its own, which price_status lists whole. The document `acq price show --json` prints. Read it before price_set or price_clear on a target that has a row of its own: they name the revision they replace.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `league` (string | null) — The league to read the target in; omitted, the league the facts hold it in, so an address an answer printed reads back as printed.
- `realm` (string | null) — The realm of an item or character target (pc when omitted); a tab or substash address carries its own, and a realm given beside it must agree.
- `target` (string, required) — One address: `item/<id>`, `character/<id>`, `tab/<realm>/<id>` or `substash/<realm>/<parent>/<id>`. An answer holds a target as an object, `{scope, realm, parent, id}`: the address is its parts in that order joined by `/`, the absent ones left out.

### `price_status`

The listing state of one league, counted (no daemon, no network): what every item, tab and character is priced as — by hand (a row this server or the CLI wrote), in game (an item's note, then its tab's name, read only where the tab is public), how the two stand — as the counts and the row accounting, without the listings themselves. `counts.by_effective` says who decides each item's price (game, manual, none, unresolved — a row that cannot be read could decide), `counts.by_relation` how the two sides stand (none, manual_only, game_only, agree, conflict); `rows` accounts for every hand-written row: how many apply here, which name nothing in the facts (`unmatched`, each row whole — `value`, `from`, `revision`, `updated_at`, `written_via` — since no listing carries it), which cannot be read, which belong to other leagues or realms. The document `acq price status --json` prints. price_list names the items; price_show is one target.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `league` (string | null) — The league; Standard when omitted.
- `realm` (string | null) — pc (the default), xbox, sony or poe2.

### `reference_currency`

The currency table this build ships (no store, no daemon, no network): every row — `tag`, the word a price cites; `emit`, the word the game writes in a note; `aliases`, legacy words that resolve to it; `display`; `retired` where the game no longer writes it; `evidence` — with the table's version and sources. `word` resolves one word instead, exact and case-sensitive: `{word, version, currency}`, or a refusal naming the word and the version. The document `acq reference currency --json` prints.

- `word` (string | null) — A tag, the game's word, or a legacy alias to resolve, exact and case-sensitive; omitted, the whole table.

### `refresh_plan`

Compile the stored sync policy + facts on record into a RefreshPlan for one (realm, league): the explicit, bounded action set applying would execute — stash listing and tab fetches, the realm's character listing and character fetches, each facet as the policy covers it — with per-action reasons, skipped tabs and characters, unknown ids, and a coarse wire estimate. Offline — sends nothing, spends nothing. A running daemon adds its read-only quote (ETA + rate-limit headroom; never spawned for this); `quote_note` says why one is absent. `notes.league` names the plan's league when the account's fetched league list does not hold it (`list_fetched_at` null: no list was ever fetched), and `notes.no_characters_listed` says the policy covers the league's characters and the realm's character listing names none in it. Review the plan, then hand `plan` to apply_plan.

- `account` (string | null)
- `league` (string | null) — League name; defaults to "Standard".
- `realm` (string | null) — Realm: pc (default), xbox, sony, or poe2 (a poe2 plan can carry character work only).

### `search`

Item search over the shared store (no daemon, no network): a query in the language `describe` prints, asked of every item in scope. The arguments are the request: {} is every item; {"query": {"text": "class:ring rarity=rare"}} is a query, and {"query": {"trade": a trade site URL}} a site search translated to one. The answer is one JSON document, its keys in this order: `query` (the text as understood, and its tree), `scope` (account, realm, `items` every live item in scope before any term, what was and was not fetched: `never_fetched` counts the tabs, their pages and the characters a listing names and no fetch has filled, and no answer says what they hold, a count of none or of many; `never_fetched_by_type` is the same by tab type, a character's `character`, each counted as the `tabs` tool counts a type, and `tabs` lists a league's tabs, `never_fetched_leagues` naming the leagues that hold a never-fetched tab, the most first), `total`, `rows` — id, name, base, rarity, place by name and id — a tab's page with no name of its own has `name` null and its tab in `parent` — with the cell the item sits in (`place.cell`, GGG's x and y, in a tab or an inventory) and when that place was last fetched (`place.fetched_at`), and the lines each term touched with their values, the term named by its `path` in `terms`, never the item's body, which is `show` — then `view`, and last `terms` (for each term how many items matched, failed, lacked the thing or were undecided — each term alone over every item in scope, never over the matches, which are `total`; a pattern term's `resolved` is what it matched there, its `rest.denominator` `scope`) and `basis` (what the answer was computed from). Rows past the limit are counted in `view.rows.left_out`, and `view.rows.next` is the request for the rows after: send it back whole. A count holds the request that returns exactly its members where a next step hangs on it — what is undecided, what holds only together, what a key could not place (`none`, `undecided`), what an ambiguous trade clause's other reading adds or drops, and each term's matched where nothing matched — and every other count is its number alone: `view.routes: true` asks for every count's. A zero total offers requests under `zero.offers`: any request an answer holds is sent back as printed. A count-first look is {"view": {"counts": {"keys": ["tab", "rarity"]}}}; the vocabulary of lines is the key `line`, or `line:<text>` narrowed. A key is one entry of `keys`: a terminal's list `line:resist,life` is ["line:resist", "line:life"], and a comma inside an entry is part of its text. A time is seconds since 1970, UTC. `describe` and the messages name a terminal's flags: --count, --cross, --sum, --sort, --desc, --limit, --explain and --routes are `view`'s fields, --context is `context`, --realm and --membership are `scope`'s, and --next is `view.rows.next` sent back. A refusal is a result marked isError: `error`, `kind`, `readings` (what may have been meant, as a terminal would type it: a query text, a name, a flag or a whole `acq` command) and, where a way on is a search, `offers` (the same as requests to send instead).

- `basis` (object) — Carried by a continuation, as an answer's `next` holds it; never written by hand.
- `context` (string) — "matches" (the default), or "corpus": the view over every item in scope, the query set aside.
- `count` (integer) — Beside `request`, the count it was printed with: the answer then says under `before` where the count has moved.
- `counted_at` (object) — Beside `request` and `count`, the `basis` of the answer the count came from: the answer then says under `before` wherever the basis has moved.
- `query` (object) — {"text": a query in the language `describe` prints} or {"tree": the tree an answer returned}, never both. Omitted: every item in scope. A refinement is the old text in parentheses and a new term. Or {"trade": a trade site search}: its URL, its id or its query JSON as a string, or the query JSON as an object (PoE1), translated with no network to the text a person would type; the answer's `query.trade` holds every clause with its status — exact, ambiguous, unsupported, listing_only, disabled; an exact one with a term of its own its `at`, `term` and `path` alone, any other — a sum's filter, a group, a clause not exact — the site's filter and what the catalogue says of it — the `remainder` that did not run, and `fidelity`, how far the text is the site's search: exact, ambiguous where a clause ran as the site may not read it, or partial where the remainder is not empty, the answer then not the site's search. An ambiguous clause whose other reading is known carries `other`: that reading, and the items in scope it `adds` and `drops` against the query as run. Never how far the items are the site's: the answer is over the items the store has fetched, priced or not — what it never fetched is `scope.never_fetched` — and the site shows public listings, a tab's being `tab.public`. A URL's realm is the scope, so `scope.realm` beside one is the URL's or nothing; an id or JSON takes a realm as a text does. A `text` sent beside `trade` must be the one it translates to, as `view.rows.next` sends it: an edited text is refused — drop `trade` to run the edit as your own query. `describe` with names ["trade"] says what each clause becomes.
- `request` (object) — In place of the fields above: a request as an answer holds one — a count (`count`, `request`, and `denominator`, what the request searches: the scope, never the share the count is of), `view.rows.next`, or an offer — sent whole, as printed.
- `scope` (object) — What is searched: {"account": a username or uuid, needed only when several accounts are known; "realm": pc, xbox, sony, poe2 or all, needed only when the store holds several; "membership": "live" (the default); "all", which adds removed items, each row marked with when it left; or "removed", the removed items alone: what has left the stash and the characters}. Under all and removed the answer's scope counts the live items as `items` and the removed as `removed`, whichever were searched.
- `view` (object) — One of: {"rows": {"limit": N, "sort": a value, "desc": true}}, the default, 20 rows where no limit is given; {"counts": {"keys": [a key, …], "sum": a value, "limit": N}}, a table for each key and no rows; {"cross": {"keys": [two keys]}}, one crossed table; {"explain": {"path": a node's path, a term's as `terms[].path` gives it}}, the total with that node forced true and forced false. Beside any of them, "routes": true gives every count its request, a terminal's --routes; alone, {"routes": true} is the default rows. `describe` with names ["counts"] lists the keys. A sort's value is a field (reqlevel), a computed value (pseudo.total_res), a line's number (line("# to maximum Life").arg1) or a sum of one (`sum("# to maximum Life")`), spanning every source unless `source=` names one; an item that lacks it is last, ascending or descending.

### `set_sync_policy`

Write the per-account sync policy (validated strictly, compare-and-swap on if_revision). Sends nothing — intent is local; the network cost appears only when a plan is applied. Each realm the value names replaces that realm alone; the others stay, a realm named with no leagues is removed, and `replace: true` writes the whole policy instead. Replacing an existing policy requires if_revision (from sync_policy) either way; a stale or missing revision is a conflict, never a clobber. Returns the stored row, the whole policy as it now stands, and `league_notes` when the value names a league the account's fetched league list does not hold: each such league with `list_fetched_at`, when that list was fetched, null when it never was (a `leagues` job fetches it). Nothing refuses on a note.

- `account` (string | null)
- `if_revision` (integer | null) — The revision this write replaces, from sync_policy. Required when a policy exists (replacing intent you have not read is refused as a conflict naming the current revision), with `replace` too; omit only to create the first policy.
- `replace` (boolean | null) — true writes the whole policy: every realm `value` does not name is removed. Default false: the realms `value` names, the rest kept.
- `value` (object, required) — The sync-policy value, e.g. {"version":3,"realms":{"pc":{"leagues":{"Standard":{"tabs":"all","characters":"all","max_age_seconds":3600}}}}} — per league, `tabs` and/or `characters` ("all" or an id list; absent means no coverage of that facet; an entry covering neither is refused). `tabs` is refused under realm poe2 (stashes are PoE1 only); `characters` is taken under every realm. Older values still parse: a version-1 top-level `leagues` map as realm pc, and version 1/2 as tab coverage only. Validated strictly before anything lands — a typo'd field is refused, never half-honored. Each realm it names replaces that realm's stored policy, every league of it; a realm it does not name stays, and a realm named with no leagues ({"poe2":{"leagues":{}}}) is removed.

### `shop_render`

The forum shop pages for one league, rendered for a person to paste by hand; this server posts nothing and reads no forum (no daemon, no network). One link code per hand-priced item under its price's spoiler, in pages of at most `size` characters, each page labelled n of N: `pages` (each `text` is what to paste), `posted` (the items on them), `left_out` (the first 50 items left off for a reason, the blocked first, each with its `cell` — what the game already lists or a skip is omitted, a case the forum has not been observed for is blocked — and `left_out_total` counting them all; `expand: true` lists every one, the items nothing applies to too, as `off_page_listed` says), `counts` (every item by its cell; the items nothing applies to in `off_page`), `policy` (each cell's rule and count) and `freshness`: whether the sync policy covers the posted items and which of them are older than its window, with the refresh that would renew them — reported, never enforced. `page` returns one page's record alone. The document `acq shop render --json` prints.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `expand` (boolean | null) — List every item left off in `left_out`, past the first 50 and the items nothing applies to included (some 200 bytes an item; a league holds thousands); they are counted either way.
- `league` (string | null) — The league; Standard when omitted.
- `page` (integer | null) — One page alone, by its number from 1: that page's record in place of the whole render.
- `realm` (string | null) — pc (the default), xbox, sony or poe2.
- `size` (integer | null) — Characters per page, the template included: the forum's hard limit when omitted.
- `template` (string | null) — The page's text, holding `[items]` exactly once, which each page replaces with its items; omitted, a page is the items alone.

### `show`

One item as the search derives it, live or removed (no daemon, no network): its place, its fields, class, category and price, and every line with its kind, template and numbers. `against` adds why the item does or does not match a query: the root's outcome and each node's — a term's `matched`, `failed`, `lacked` or `undecided`, a group's `match`, `no_match` or `undecided`. `body` adds the stored body, verbatim. An id that is a tab's or a character's is refused and offers the search that lists it. A refusal is a result marked isError, as `search`'s is.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `against` (object) — Why the item does or does not match a query: `{"text": …}`, `{"tree": …}` or `{"trade": …}`, as a request's `query`.
- `body` (boolean | null) — Also return the body as the store holds it, verbatim.
- `id` (string, required) — An item's id, whole, as an answer printed it.

### `store_status`

Store file path, size, and row counts (no daemon, no network). `leagues` counts the league listing's rows and `league_list` says whether that listing was ever fetched (`acq leagues` or a `leagues` job fetches it); characters and tabs carry their league names whether or not it was. `refused_bodies` counts bodies the store would not take, which `acq store refused` lists.

- `account` (string | null)

### `submit_job`

Submit a job to the daemon and return its id immediately; poll job_status then fetch job_result. In real-GGG mode the daemon must already be running (a human starts it; this server never spawns one there).

- `account` (string | null) — Account to run as; required when several sessions are live.
- `kind` (string, required) — Job kind: profile, characters, character, leagues, stashes, stash, refresh (mock daemon also: sleep, fetch, whoami).
- `params` (object) — Kind-specific params, e.g. {"league": "Standard", "id": "..."} for stash. Passed verbatim; visible to every connected client.
- `priority` (integer | null) — Higher runs sooner (default 0).

### `sync_policy`

The per-account sync policy (declared coverage + freshness, an annotation) with its revision — the intent refresh_plan compiles. Reads the store; no daemon, no network. `policy` is null when none is set.

- `account` (string | null)

### `tabs`

The stash tabs of a league, counted first, from the shared store (no daemon, no network): how many tabs, fetched, never fetched and folders, how many items, and the same by tab type (`by_type`, the most items first); then `rows`, the tabs listed — every one where the league holds thirty or fewer, else the ten with the most items (`listed`: `all` or `most_items`) — each with its type, item count and fetch time, a substash naming its `parent`. `left_out` counts the tabs not listed; `expand: true` lists them all (some 220 bytes a tab). `type` and `never_fetched: true` select the tabs listed — the never fetched of one type by name, which a refresh takes — under the league's counts, `selected` counting them. A name ending ` (Remove-only)` is GGG's mark on a tab whose items can only be taken out; a search asks it as `tab.remove_only`.

- `account` (string | null) — Account selector (username with or without `#discriminator`, or uuid); required only when several accounts are known.
- `expand` (boolean | null) — List every tab of a league of more than thirty, or of the selection, in place of the ten with the most items.
- `league` (string | null) — League name; defaults to "Standard".
- `never_fetched` (boolean | null) — Only tabs never fetched.
- `realm` (string | null) — Realm: pc (default), xbox, or sony.
- `type` (string | null) — Only tabs of this type, as GGG names it (UniqueStash, MapStash, PremiumStash …; `by_type` lists them).
