# The C++ issues the Rust release answers

A draft for release step 5 (the brief `RELEASE-PLAN.md` at `d0ab421e`): the eight open issues of `smallcatlabs/acquisition-qt` on 2026-10-19, each beside what in the Rust release `v1.0.0-beta.1` answers it, the test or ruling that holds it, and a closing note in the owner's voice to post or edit. Read on the tree at `081cf561`; every behaviour named was run on that build in a mock world over a scratch copy of the release seat's pristine store (`ACQ_PROVIDER=mock`, no daemon, nothing sent). The owner closes the issues; nothing here was posted, commented or labelled.

| Issue | Asks | Rust behaviour | Test or ruling | Closing note |
| --- | --- | --- | --- | --- |
| #229 Search: three min/max filters can never match, two unguarded reads | Crit, block and map tier filters never match; a stack size and a mod match are read unguarded | `acq search` / `search`: `critical_strike_chance>=7` (914 items), `chance_to_block>=25` (145), `map_tier>=16` (369), each read from the displayed value; the stack size is GGG's number, and a line's template comes from its own text, so nothing is matched against a second table; what cannot be read is reported, never a panic | C114, C101, C47, C93; `acquisition-search/tests/properties.rs`, `derive.rs` (`no_body_panics_the_deriver`), `unread.rs`. Gap: a map whose base names no tier (Shaper Guardian Map) has no `map_tier`; park in `decisions/trade.md`, trigger: a registered source of map tiers | Fixed in the Rust release, v1.0.0-beta.1: `acq search` (and the `search` tool for agents) has `critical_strike_chance`, `chance_to_block` and `map_tier` fields that read the values the game displays. Item parsing no longer depends on string splitting or a second match against a template, and anything it cannot read is reported as such. Closing here. |
| #187 Headless Support | Would patches for an agent-driven, headless client be welcome? | `acq`, a full command line with `--json` on every command, and `acq-mcp`, an MCP server over stdio with 25 tools (search, pricing, refresh plans, jobs), both clients of one background daemon that alone talks to GGG | C11, C13, C14; `acquisition-mcp/tests/mcp_reference.rs`, `acquisition-cli/tests/cli_reference.rs` | Thank you for the offer. Acquisition v1.0.0-beta.1 is a rewrite built headless first: the `acq` command line and the `acq-mcp` server let an agent fetch, search and price without the GUI, all through one rate-limited daemon. I'd love your feedback on it in the new repository. |
| #149 Hidden tabs still included in the tab refresh | A tab hidden in search but checked is still refreshed | `acq policy set` names the tabs (or `"all"`) to keep fresh; `acq refresh --plan` (`refresh_plan`) lists exactly the requests an apply sends, and the search has no hidden-tab state to disagree with it | C36, C37; `acquisition-plan/src/lib.rs` (`a_named_folder_covers_its_children_at_once`), `acquisition-cli/tests/plan_json.rs` | In v1.0.0-beta.1 what gets refreshed is only what your sync policy names, and `acq refresh --plan` shows every tab it will fetch before anything is sent. Search filters have no effect on it. Closing as answered by the rewrite. |
| #148 Tabs with buyouts not locked for refresh consistently | Priced tabs should reliably be kept in the refresh | By design no price locks a tab: `acq shop render` (`shop_render`) names every priced tab outside the sync policy and every priced item older than its window, with the `acq policy set` that fixes it | C72; `acquisition-plan/src/shop.rs` (`c72_coverage_staleness_and_positions_are_reported_never_enforced`) | v1.0.0-beta.1 takes a different route: pricing never changes what is refreshed, so there is no lock to get out of step. Instead `acq shop render` tells you which priced tabs your sync policy does not cover and which prices are stale, and how to add them. Closing as answered. |
| #132 Modifiers with non-integer values aren't searchable | Decimal mod values cannot be searched | `acq search 'line("#% of Physical Attack Damage Leeched as Life").arg1>=1.5'` matches 26 items (1.78% among them); sums and sorts over decimals are exact | C90, C92; `acquisition-search/tests/surface_faults.rs` (`c92_a_sum_of_decimals_is_exact_and_no_order_of_occurrences_changes_it`) | Fixed in v1.0.0-beta.1: `acq search` (and the `search` tool) reads every number of a mod as written, decimals included, so `line("#% of Physical Attack Damage Leeched as Life").arg1>=1.5` works. Closing here. |
| #122 Show item prices synced with poe.ninja | Show market prices from poe.ninja or a similar API | None: the release reads no price feed; `acq price` covers the prices you set and the game's notes only | Park in `decisions/pricing.md`, "Third-party price feeds … under a governed surface"; trigger: currency ratios or a "suggest a price" consumer | v1.0.0-beta.1 does not show market prices yet; it handles your own listing prices (`acq price`) and the shop post. A price feed would need its source cleared first and someone asking for currency ratios or suggested prices, so I'm leaving this open as the place to ask. |
| #38 Not updated for the divine/exalt swap | The currency handling still treats exalted as worth more than divine | The currency table (`acq reference currency`, `reference_currency`) lists each orb by its tag, `divine` and `exalted`, with the words the game writes; it carries no value order, and nothing ranks one currency above another | C68; `acquisition-cli/tests/reference_currency.rs` | v1.0.0-beta.1 has no built-in ranking of currencies, so the old exalt-over-divine order is gone; `acq reference currency` lists each orb with the words the game uses. | #25 Handle buyout prices with "/" in them | Accept fractional prices like `79/20` | `acq price set <target> b/o 79/20 chaos` (`price_set`, amount `"79/20"`) stores the ratio as written; a game note's ratio is read too (`price.lot` in search) | C67, C69; `acquisition-plan/src/price.rs` (`c67_the_amount_is_a_four_place_decimal_or_an_unreduced_lot_pair`), `game_side.rs` (`c69_a_ratio_is_a_price_in_a_note_and_invalid_in_a_tab_name`) | Fixed in v1.0.0-beta.1: `acq price set` takes a `wanted/lot` price such as `79/20 chaos` and keeps it exactly as written, and ratio prices in your item notes are read the same way. Closing here. |
