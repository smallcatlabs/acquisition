# Report — acq-mcp release seat

## 1. Before touching anything

### What the brief told me (the brief)
acq-mcp is the MCP server of Acquisition, a PoE inventory tool; one account, GERWARIC, a copy of a real ~50 MB collection with the person's prices, is in the store; there is no login and no daemon in this world, and every call is pointed at a mock API and the store under W (the brief). None of this counts as the README's or the tool's.

### What the README alone told me (before any call)
- **Can do:** read a local store of stash tabs and characters offline (search, describe, show, tabs, characters, item_events, store_status, accounts); price items and render forum shop pages (price_status, price_list, price_show, price_set, price_clear, shop_render, reference_currency); keep a league fresh by sync policy + plan (sync_policy, set_sync_policy, refresh_plan, apply_plan); run fetch jobs through a daemon (submit_job, list_jobs, job_status, job_result, cancel_job, daemon_status). 25 tools ("Your agent").
- **Needs:** store and pricing tools need no daemon, no login, no network. Fetching tools need the daemon, which needs a login (`acq auth`, at a desktop, keyring) and the network to GGG. Against GGG acq-mcp "never starts" a daemon; it uses one the person started, which idles out after 60 s unless `ACQ_IDLE_SHUTDOWN` is set.
- **Before an agent can use it:** unpack the archive, keep three binaries together, put on PATH; `acq auth` for the person's own account (or `ACQ_PROVIDER=mock acq auth` for the stand-in); add the `mcpServers` block to the host config. The README's sample config sets `ACQ_PROVIDER=mock` — "leave it out for your own account".
- **What I would not call without asking:** anything that writes the person's intent — `price_set`, `price_clear`, `set_sync_policy` (README Known gaps: it replaces the whole policy, every realm); anything that spends their rate limit or fetches — `apply_plan`, `submit_job`; `cancel_job` on their jobs. Reading is free.
- Pointers I cannot follow here: `AGENTS.md`, `CLI-REFERENCE.md`, `CONTEXT.md`, `decisions/*.md`, the `crates/...` source links in Knobs, `SECURITY.md`, `CONTRIBUTING.md`. The README defers each verb's flags to `--help`/`CLI-REFERENCE.md`; for the MCP tools I must rely on the tool texts.

### What `open` told me (call 1) that the README had not
- The server announces its provider: "Acquisition (provider: mock)" — so this world's server runs against the stand-in; the README's sample config sets that, but the README never says the server will tell you which provider it is on.
- How to begin: `search` with no arguments, then `describe` with `names ["fields"]`; `describe` whole is over 100 KB. Refusals are results marked `isError` with `readings` and `offers`; counts carry requests to send back "as printed".
- Writes are compare-and-swap: `price_set`, `price_clear`, `set_sync_policy` must name `if_revision` over an existing row, and the MCP tools are "stricter than `acq price set`/`clear`" — the README's tour shows `--if-revision` as optional.
- Each write returns a receipt (`target`, `written`, `prior`, `in_facts`) and the tool text says how to undo each kind.
- Target addresses: `item/<id>`, `character/<id>`, `tab/<realm>/<id>`, `substash/<realm>/<parent>/<id>`.
- `submit_job` kinds: profile, characters, character, leagues, stashes, stash, refresh (mock also sleep, fetch, whoami).
- Tool-specific realms: `tabs` takes only pc/xbox/sony; `characters` and pricing take poe2 too.
- 25 tools, same names as the README lists.

### What the README told me that `open` did not
- That a login is made with `acq auth` at a desktop; that the daemon idles out after 60 s and how to start one with `ACQ_IDLE_SHUTDOWN=3600`; where the store and logs live per platform; the knobs (`ACQ_STORE_DIR`, `ACQ_NO_SPAWN`, rails); that `policy set` replaces the whole policy across realms (the tool text says only "replacing a policy must name the revision"); that a moved item may lose its forum link. `open` never names `ACQ_PROVIDER`, `ACQ_IDLE_SHUTDOWN` or `acq auth` by command — only "Login is done by the human via the `acq` CLI".

## 3. Faults
Worst first.

1. **The daemon advice the tool gives cannot be followed as printed in the provider it is running in.** `submit_job`/`job_status` (calls 45, 47) tell the person to type `ACQ_IDLE_SHUTDOWN=3600 acq auth check`, while the same server announces `provider: mock` (call 1) and its store is `store/mock` (call 3). Typed as given, that starts (or tries to start) a `ggg` daemon for another provider and, if the store is not in the default place, another world. It should print the command for its own provider and store dir (`ACQ_PROVIDER=mock`, `ACQ_STORE_DIR=…`), or say they must match. Refusal warranted (no daemon): yes. Enough to recover: no, for anyone not on the default. Hits a person too — the person is the one who types it.
2. **Two refusals are JSON-RPC protocol errors, not tool results.** `tabs` with an unknown account (call 50) and `refresh_plan` for an uncovered league (call 46) come back as `{"code": -32603, "message": …}` — "internal error" — with no `isError`, `kind`, `readings` or `next`, while `search` refuses the same unknown account as a proper document with the right reading (call 52). The instructions promise "a refusal is a result marked isError with readings and offers". Warranted: yes both times (my request was wrong). Enough to recover: call 50 points to the CLI (`acq accounts`); call 46 says nothing of what to do (`set_sync_policy`). A host may also show -32603 as a server crash. Agent only (a person on the CLI sees the CLI's own message).
3. **`shop_render` cannot give its counts without its 160 KB item list.** Call 37 was 160,473 bytes; the door cut it at 3,000 characters and I lost the end of `policy`, all of `counts`, `left_out` and `freshness`. `page` (call 38) returns only the page. There is no `limit` on `left_out` and no counts-only view; the person asked "what was left out", and I could answer only from the first rows of `policy`. A host with a smaller limit than 60 KB would lose more. Agent mostly; a CLI user gets a long screen.
4. **Invalid notes are counted but cannot be found.** `price_status` counts `invalid_notes` 1 (Standard) and 3 (Allflame) (calls 21, 22); no `price_list` filter, `relation` or `effective` value selects them, and the search has no field for it that I found (call 27). "Is anything wrong with my prices?" then has a known-unknown answer. Refused bodies are the same: `store_status` counts 4 and points at `acq store refused`, which has no MCP tool (call 3). Both: person and agent (the CLI has `store refused`; for notes I don't know).
5. **The README's sample host config defaults the agent to the stand-in.** "Your agent" shows `"env": { "ACQ_PROVIDER": "mock" }` and says to leave it out for your own account. The block people copy is the wrong one for the common case. Person.
