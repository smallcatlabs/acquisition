## 1. Before touching anything

**What the brief told me (the brief):** the tool is `acq`, for Path of Exile inventory; the store holds `GERWARIC` (no session) and a second account I log in; the world is a mock with no keyring; no terminal/browser.

**What the README told me:**
- Can do: download stash tabs/characters via a daemon (`acqd`), search offline, set prices, render forum shop pages to paste; also `acq-mcp` for agents. Never posts to the forum, never reads the trade site.

- Would not dare run without asking: `acq policy set` (replaces the whole policy, all realms - Known gaps), `price set`/`price clear` on a real store, `refresh --apply`/`--all` (an hour of rate-limited requests against the real GGG), `store import`/`rebuild`, `auth logout`, `daemon stop` (loses a keyring-less login), `ACQ_PROVIDER` changes. ## 3. Faults
Worst first; "person/agent" says who meets it.
1. **`--json` output of `shop render` is 7478732 bytes and `price show tab` 173756 bytes** (calls 72, 71) against 6168 and 515 bytes as text (calls 62, 42). The README says "every command takes `--json`" and a program is promised "one JSON document"; a program asking for the pages of the shop gets every item listing with them. The door printed only the first 3000 characters, so I could not check the document ends well. Warranted? my request was fine. Enough to recover? Nothing said; `--page N` with `--json` may be the way, I did not try. Person and agent both.
2. **`kind` is missing from some JSON failures**: price write with wrong revision `{"error":"annotation ... is at revision 4 (re-read and retry)"}` (call 81), cleared row (call 78), job failure (call 83); present on `unknown_account` and `item_not_found` (calls 74, 76). README: "a failure is `{"error":…}`" so the README is true, but `acq --help` says `{"error","kind"}`. A program cannot switch on a kind for the cases that matter most (write conflicts). Agent mostly.
3. **A write refusal speaks the store's internals**: `annotation item/<id>/buyout is at revision 4` (call 80) - "annotation" and "buyout" are not words the person used (`price`, `exact`); and on a cleared row `annotation no longer exists (re-read and retry)` (call 77) hides that the row was cleared (by me) and that it still has a revision (call 79 got 4, since clears count). Refusal warranted: yes (wrong revision). Enough to recover: partly - "re-read" says what to do, the current revision is named in one case only. Person and agent.
4. **A failed job command starts a daemon** (calls 92, 93): "not logged in" was knowable without one. It leaves a daemon running that a person then has to find (`daemon status`, `daemon stop`). Person and agent. (Mock provider; real provider untested.)
5. **First-time price writes print no way back**: `price set ... exact 5 chaos` -> "revision 1, was unset" with only a "reads it" next step (calls 55, 56), while the replacement prints the exact undo command (call 58) and the help says set "Prints ... how to put that back". The way back (`price clear`) is learnable, and `clear` does then print its own undo (calls 63, 64). Person and agent.
6. **Two ages for the same store**: `tabs` says the biggest tabs were fetched "41d ago" (call 20), the search scope says "newest 4d ago" (call 25) and `store events` says 0 in 24 h (call 23); nothing says the 4-day-old fetches are the price-test tab/listing and not stash content. Person and agent.
7. **`daemon stop` logs the session out** without a keyring - said in its output (call 16, 87) but not in the README's recipe for a longer daemon, which says "while none is running" and never says how to make none run. Person and agent. Not a refusal; the tool was honest, the README was incomplete.
8. `access_expires_in_seconds: 59` right after login (calls 7, 17) and `~50s` (call 8) read as an expiring login; it renews on use (call 8's text says so). The JSON field alone misleads an agent.
9. `price status` counts "1 invalid notes" and "3 skipped" (call 37) with no verb I found that lists the invalid note (`price list` has no such filter, call 39). Person and agent.
10. `price list --expand` has no `--limit` (call 44) and the one conflict tab produced 21283 bytes (call 45). Minor.
11. `acq version` help promises mtime in the line; the text omits it (call 4 vs 6). Minor.
12. Shop page labels start with a space (` ~price 5 chaos`, call 62); I could not tell whether the forum minds. Person.
