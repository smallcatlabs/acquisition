# The skeptic on the draft plan

Codex (`codex-cli 0.171.0`, read-only sandbox), a model outside the author's family (C177), on 2026-11-25, given `NEXT.md` as first drafted and this charge and nothing of the author's reasoning: try to break it; for each step check its claims against the code and the rulings by path and line, give the smallest input, ruling or dependency edge that makes it wrong, larger than stated or mis-ordered, and say what it did not see; say what the plan as a whole misses; end each step SURVIVES, WEAKENED or DIES. The answer is whole. What it changed is the last section of `NEXT.md`.

The programme has useful pieces, but its authorization, review classes and dependency order do not hold as written. I ran only read-only inspection: no cargo, `acq`, or network requests.

Paths below are relative to the repository root.

1. **A1 — The world.** The proposed home works **if `world.rs` is included independently**, rather than added to the client harness’s module tree. The door grep scans only frontend `src` trees (`tools/arch-check.sh:555`); the layout check scans top-level test files (`:617`). Verbs already links store and plan. But replacing the pricing seed with three accounts breaks the existing unnamed `price_status({})` call (`crates/acquisition-mcp/tests/pricing_tools.rs:255`), correctly refused under C121 (`decisions/frontends.md:15`). Variants must preserve intentional single-account cases. **WEAKENED — the placement works, but conversion is more than replacing seed functions.**

2. **A2 — Counted tasks.** Its claimed instrumentation does not exist: `rpc` receives and parses lines without accumulating bytes or calls (`crates/acquisition-mcp/tests/harness/mod.rs:270`). More fundamentally, one call returning the wrong empty answer beats three calls returning the correct items. Each task needs independently specified results alongside counts; the existing journey supplies precisely such expected counts and identities (`crates/acquisition-client/tests/harness/journey.rs:31`). A scripted sequence also measures that script, not whether new wording teaches a blind reader. **WEAKENED — retain the measurement, but require correctness and keep the blind seat as separate evidence.**

3. **A3 — Small machines.** The concrete counterexample supports the cut: acquire `a`, queue another `a`, acquire `b`, rekey `a→b`, release the first permit. Removing `b` from `active_policies` then admits the waiter beside the remaining live `b` (`crates/acquisition-daemon/src/gate.rs:105`, `:198`, `:234`). Deriving occupancy from `active` removes that discrepancy. The trial prints findings without failing (`audits/whole-review-2026-11/trials/admission-explorer.patch:276`); turning it into an assertion is essential. Its exploration never exercised composition (`trials/admission-explorer.md:90`). **SURVIVES — the occupancy fix is independent and concrete, provided its claim stays limited to the gate.**

4. **A4 — Builder’s entry.** The README correction is justified (`README.md:5`, `:21`). The reading change is a workflow change, so “documents, no review” is insufficient under C175 (`decisions/process.md:26`). Also, `pack --path` prints uncited entries only as headlines (`tools/bothy.py:773`), not their qualifications: replacing whole-file reading is a substantive tradeoff, not eliminating identical material. **WEAKENED — make the reading change an explicit, reviewed workflow decision; the documentation correction stands independently.**

5. **B1 — Realm and league.** “No new ruling” fails. C96 governs searches and explicitly defaults them to **every league** within a realm (`decisions/search.md:23`); it neither mandates sole-league selection nor prohibits other reads spanning leagues. C58 governs coordinates and decode defaults (`decisions/store.md:27`), not the definition of “held.” Existing clap defaults occur at an input decode boundary (`crates/acquisition-cli/src/cli.rs:168`). Smallest unresolved input: a newly logged-in account, no facts, policy naming Rehearsal. Sole-held selection cannot bootstrap it without choosing another authority. Refresh’s changed selection affects live requests, an owner class under C170. **DIES — the proposed rule needs an owner ruling before implementation.**

6. **B2 — Ways in documents.** The first offer slice is credible, but the universal acceptance check contradicts its own scope. `price set item/<id> exact <amount> <tag>` is deliberately incomplete (`crates/acquisition-cli/src/shop_cmd.rs:428`); a person’s act need not be an MCP tool. Existing `Surface::request` permits no request, and `offer` consequently drops that way (`crates/acquisition-verbs/src/refusal.rs:161`, `:295`). Merely adding variants can therefore silently lose guidance. **WEAKENED — distinguish executable offers, incomplete instructions and human actions before defining the check.**

7. **B3 — Shared words.** Golden files can remain unchanged; that is not proof of unchanged behavior. Moving even one fragment into search changes its build digest (`crates/acquisition-search/build.rs:29`), invalidating old continuations under C100 (`decisions/search.md:29`), while golden normalization masks that digest (`crates/acquisition-cli/tests/harness/mod.rs:1127`). The larger move also hits an edge: `ShopRender` lives in plan, but its renderer constructs verbs’ `Way::RefreshPlan` (`crates/acquisition-cli/src/shop_cmd.rs:244`). Plan cannot link verbs through client/search (`tools/arch-check.sh:484`). **WEAKENED — preserve normalized goldens, but split command-bearing renderers or supply an explicit seam.**

8. **B4 — Page projections.** The intended projector needs more than `submitted()`. Change `<button name="toggle_item" value="r1">Open</button>` to the same button with another name: text stays identical, submission changes, and the helper ignores both buttons (`crates/acquisition-cli/tests/harness/submitted.rs:111`, `:165`). Input submit controls are also skipped (`:129`). Project each clickable submitter’s request, not merely a form’s default fields. The projector and recording seam change shared harness behavior, invoking C175. **WEAKENED — the direction stands, but its parser coverage and review class are understated.**

9. **B5 — Frontend doors.** Private `Account` fields help, but do not replace the door grep: `Store::open` remains publicly available without constructing an `Account`. A token-prefixed router also cannot infer that a handler mutates: accidentally registering `get(saved_clear)` still passes a generic GET allowance. Today method selection is explicit per route (`crates/acquisition-cli/src/web/mod.rs:644`). Finally, making frontend facts read-only breaks the existing `store.rebuild()` path (`crates/acquisition-cli/src/store_cmd.rs:1111`), requiring a deliberate replacement. **WEAKENED — this needs separate designs for route registration and maintenance writes, with narrowly named retirements.**

**How it runs.** The classes are not equivalent to C175/C176. A1, A2 and B4 change harnesses; A1 adds a tool; A4 changes workflow. Repeated moves touching the harness still need review. Conversely, C176 supplies a maximum and continuation conditions, not a fixed one-review allowance for surfaces (`decisions/process.md:26–27`).

The order hides dependencies: B3’s full shop move needs B2’s seam or another design; B2’s first slice already supplies explicit realm and league, so it need not wait for all B1. B1’s necessary ambiguity refusals can also worsen A2’s call count, contradicting the blanket “may not get worse” rule.

The retirement list misses what the programme adds: projection parsing, task counters, variant machinery, translation tables, lane integration and new orchestration rules. C182 requires checking whether existing structure can hold them first (`decisions/process.md:38`).

The larger omission is **identity continuity before release**. A rename updates the username while explicitly orphaning its facts file (`crates/acquisition-store/src/index.rs:300`). Refetching cannot recover historical observations. The plan recognizes this and postpones it; a transition design and rename/restart rehearsal would prevent more irreversible future pain than moving renderers.
