## Noticed
- C94 clause 5 ("nothing else defines a total"): the crate already defines computed values in code, the `Derived` family in `crates/acquisition-search/src/pseudo.rs` (`pseudo.dps`, `pseudo.edps` and others, kind "derived"). They read totals or properties rather than sum lines, so they are not totals under the clause. Still, the only thing between a summing `Derived` and the shipped tree is the hand-bumped count at `pseudo.rs:662`.
- C113.1, C195.4 and C99.2 rest on `tools/arch-check.sh` check 5, which reasons about HTTP client crates (reqwest by name, "any HTTP client by another road"). Nothing refuses `std::net` in the search crate, so a raw socket would pass. This is the first reader's point, confirmed by `git grep` finding no `std::net` in `tools/`.
- C109: the depth walker's exhaustive `match` (`tree.rs:534-545`) makes a new node kind a compile error until it is scored. That is close to `caught`, but the score is the builder's choice, so the hand list in `depth.rs` decides it.
- C145: the refusal's wording table `array_missing` (`crates/acquisition-store/src/lib.rs:466-481`) has an `_ => "an item array"` fallback, so a new seam through `present_array` still refuses, with generic words. Only a seam that bypasses `present_array` breaks the clause.
- C63: the entry's `Pinned:` reads "nothing yet". The JSON half is in fact held at `store_answers.rs:119`.
