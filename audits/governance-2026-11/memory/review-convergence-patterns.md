Patterns from 4-0 and t5 round 1 (2026-10-31: four cuts of the door brief, five of the life brief, three of the design, three of round 1's; every build had one fix round).

- **Every concurrency finding was a "between".** When a statement sequence becomes a loop's two turns (judge then commit; swap then stop_admitting; closure return then join wake; compare then swap), each gap is a window. A brief that moves code into a machine or an event loop lists the sequences the code relies on being one step, and says which stays at its ingress. Ask the reviewer for exactly that lens.
- **Rules converge, inventories do not.** Enumerating events/effects drew gaps in every review; stating a criterion (which waits are decisions), a boundary rule (the loop never blocks on `shared` before leave; a scenario crosses the frontend boundary only) and where a decision is made today dissolved findings instead of patching them.
- **The worker's "raised for review" predicts the review.** Both of round 1's and step 2's real findings were things the worker had raised. Feed the raised list to the review prompt verbatim; where a raise is fixable by one rule, the fix round is cheap.
- **A retirement needs the retired test's property list first** (shape 10): three holders held less (c86, BlockingClock, responses.rs) until the properties were listed by line. Make the worker list them before naming a holder.
- **Real-time flakes live in the harness's rules, not the product**: a pacing oracle demanding exactly 0 ms on a real clock, a place rule cut at an inner paren, two runs compared whole across a second. An oracle that reads a clock-chosen value is told which clock produced it (the journal's `clock` kind), exact on a manual clock, tolerant under the pacing floor on a real one.
- **Counts: label occurrences, calls and rows apart**; a reviewer re-ran every number and found the mislabelled ones.
- **Reuse the ecosystem's shape**: the park hook is tokio's paused clock behind the project's trait, no feature split; the design's own count of waiting tasks was refuted by a spike in a day. Spike before trusting a mechanism the design guessed.
- **Read every tool result**: a pipe hid a failed gate once; a script that exited on a bad anchor wrote nothing once. Both were caught only by reading the output, not the exit of the wrapper.
- **A signal the runtime already has beats a count or a sleep** (t5 round 4): three private polls on a flight's `receiver_count` and three 50 ms sleeps "for the parked refresh to reach the gate" all stood for "nothing can run under a held send", which the park hook already knows; one primitive (`Door::quiet`) replaced them, with one rule (call it only after the held request's arrival barrier, since before it a park may be a socket read's). Ask of any wait: what does the runtime already know at this moment?
- **The wire and the journal are two records** (t5 round 4): the journal holds landed sends, account-blind for a token POST, and an aborted owner's POST never reaches it; a fixture's record is the wire. A design sentence that reads a wire fact "from the journal" is a claim wider than its evidence (shape 1), and a cold review of the brief catches it before a build does.
- **A test's `Arc::get_mut` patch names a missing builder option** (t5 round 4: `store_dir`, set only through `world`). Structure over discipline: the option goes on the builder, the patch goes.
- **Who the actor is decides the boundary** (t5 round 4): the login's callback was classed "the daemon's own socket" and kept off the door, but the actor is the user's browser, a frontend side; the two `wait_callback` tests (the listener's own reads) stay component. Name the actor before naming the boundary.
- **A first cut's findings cluster in the recipes, not the citations** (t5 round 4: twelve on the first cut, most about which fixture answers what, a default the builder installs, a script left unconsumed). Before drawing a recipe, print the doc and signature of every fixture and door call it names (a "mechanics read"); round 5a's first cut, done that way, drew six findings, one of them this same shape (a log read widening the boundary).
- **"Keep none" in a brief is a C154 violation by construction**: every private assertion a scenario drops is "held by X" or "kept", never dropped; the fix round of round 4 and a finding on 5a's brief both came from it. A token value is a boundary property only through a send that carries it.
- **Size a round by counted tests from the inventory, not by family names in a design**: the design's round 5 was 150 tokio tests across 17 files and became 5a, 5b, 5c. Two parallel read-only inventories per round pay for themselves.
- **A reader of a set knows the whole it expects from the source that defines it** (t5 round 6, the one build finding, shape 8): the comparison script took whatever shard directories it found as the run, so three downloaded shards, or one cut at CI's limit (cargo-mutants rewrites `outcomes.json` per mutant and sets `end_time` only at the end), compared without complaint. The fix read the shard count from the workflow at the run's commit and refused a missing, foreign or unended shard by name. Ask of any reader over artifacts: what defines the whole, and does the reader read that?
- **An estimate names its unit or it is wrong twice** (t5 round 6): the design said "215 toward about 120" counting occurrences; the census in rows rose to 416 because tables expand. Count rows and occurrences apart in a design's estimate as in a close's claim.
- **A ceiling trades a fast failure for a timeout under mutation** (t5 round 6): 48 mutants moved from caught to timeout once the scenarios waited to `HANG` for an answer the mutant prevents; the retired component tests failed their assertion at once. The runtime's "nothing can run" instant (`quiet`) is the fail-fast signal; a ceiling is never one. #151 holds it.
- **The baseline that waits for a named machine never runs**: dispatch the long run in CI on a tag the moment the brief names it, and compare against artifacts, not against a recollection.
- **A parameterised deadline's pin counts attempts, never time** (#148, 2026-11-01): a test that forces a deadline to zero and asserts the verdict still passes if the code ignores its parameter and waits its old literal, only slower; the wiring is held by counting the attempts (SQLite's authorizer sees each `PRAGMA` prepared: one at zero), and the mutant that restores the literal reads hundreds. Codex named it; the worker had raised it as unpinnable.

- **A mechanism waved to the worker draws a finding; a path named does not** (describe-slices, 2026-11-01): the first cut said "the smallest change the worker finds sufficient" for a refusal's offer and the reviewer traced that `Offered` carried only a search request and `searched` turned every scope offer into a reading; the second cut named `Offered` → `searched` → `Way::Describe` → each `Surface::request` and the finding closed. Before writing "the worker finds", print the types on the path and name them.
- **A test's negative case is checked against the settlement it pins** (describe-slices, third review): an anchored-definition case whose negative was "not one whose name does" contradicted a settlement that matched name or definition. Read each pin's negative as an input the settlement must refuse.
- **An argument a user types a regex into has no clap delimiter** (describe-slices): `value_delimiter = ','` would have split `^.{1,20}$`; `--count` already splits in code with the pattern taking the rest of its value, and the reviewer found the sibling before the build did. Grep the arg attributes of every flag a brief adds a pattern form to.
- **A brief's "bounded by construction" is read against the bound's unit**: `LISTED` counts entities, not bytes; the review made the claim "density control, measured cases, exceptions named". Say what the bound counts.

Related: [[orchestrating-steps]], [[claims-match-evidence]], [[simplicity-over-mechanism]].

- **A retirement line names a holder that runs (2026-11-07, 4-full-1-saved sixth review):** a `retired X; held by Y` line is for an executable test replaced by something running in the gate at that commit. A pin dropped from a brief before it was built is a dropped planned case under the ruling that dropped it, said so in the foot; asking the worker for C154 lines on it drew a finding.

- **An "every X" pin sits at X's seam, not on a list the test builds (2026-11-07, 4-full-1-pages build review):** the brief said the scan reads "every page the step records"; the worker built a list of replies in the test, and the reviewer named the pages outside it (P2). The fix moved the check into the harness's recording functions, which every golden passes through, with one list of scripts both the seam and the scan read. When a brief says "every", ask where every one passes and put the pin there; the worker's own "judged narrow" line predicted the second finding, as usual.
