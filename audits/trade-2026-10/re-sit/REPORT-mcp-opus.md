## 1. Before touching anything

**From the brief (counts as nothing the tool told me):** the tool is acq-mcp, the MCP server of Acquisition, a Path of Exile inventory tool; it fetches stash tabs and characters through a local daemon into a local store, and searches/prices/lists them, including by a pasted trade-site search (the brief). One account, GERWARIC, a copy of the person's collection with their prices; no login and no daemon here, so API-needing calls will say they cannot reach it (the brief).

**From `open` (call 1), the tool's own words:**
- What it can do: `search` over every item in the store (query language from `describe`; a trade site URL/id/JSON as `{"trade": …}` "translated to the text a person would type"), `show` one item whole, plus `accounts`, `tabs`, `characters`, `store_status`, `item_events` — all said to "read the shared SQLite store directly — no daemon, no network" (call 1).
- Prices: "No tool says what an item is worth: a price is the owner's own listing" (call 1).
- Needs a daemon: `submit_job`, `job_status`, `job_result`, `cancel_job`, `list_jobs`, `apply_plan`, `daemon_status` ("Job tools talk to the local daemon; API requests are jobs"). Login "is done by the human via the `acq` CLI"; in real-GGG mode the server "never spawns or replaces a daemon" (call 1). `list_jobs` and `daemon_status` say they only observe (call 1).
- Local writes without network: `set_sync_policy` writes intent to the store; `refresh_plan` is offline (call 1).
- Network: only via jobs / `apply_plan` through a daemon (call 1).
- What I would not run without asking the person: `submit_job`, `apply_plan`, `cancel_job` (spend their API rate limit / change the queue, and refresh the store, changing what it holds), and `set_sync_policy` (rewrites their declared intent). For T0's "without changing it" I will use only store-reading tools and observers.
- The instructions say plain `search` with no arguments is refused over a store of several realms, and that `describe` whole is over 100 KB, so name sections (call 1).

**The world as I found it (T0, calls 2–7, nothing changed):**

## 4. What the instructions and the tool texts did not say

- **A `sum(...)` from a translated trade clause is a valid sort value.** Expected in `search`'s `view` text ("a field, a computed value or a line's number", call 1). Learned in call 26.
- **Flags (`priced`) can't be count keys; use `price.currency`.** Expected in `describe fields` under `priced` (call 10) or in the `view.counts` text (call 1). Learned by refusal, call 11.
- **A tab's price-in-name prices its items only when the tab is public.** The `priced` text says "public tab name" (call 10), but only the 37 items in private '~price 40 chaos (F)' counted as unpriced made it concrete (calls 29, 30). Expected in the `price` entry of `show` (call 1).
- **`fidelity` can be `ambiguous`.** The `search` text names only `partial` (call 1). Learned in call 18.
- **The `-has:tab` bucket is the character-held items.** Not said; inferred from equal counts (calls 29, 30).
- **Which stash listing `tab.public` and `list_seen` come from.** Not said anywhere; the ages disagree (calls 5, 6, 37).
- **That `refresh_plan` lists only policy-covered tabs, not never-fetched ones.** Expected in `refresh_plan`'s text ("skipped tabs … unknown ids", call 1). Learned in call 37.
- **What `leagues: 0` and `refused_bodies: 4` mean in `store_status`** (call 3) — never learned.
- **What `container: guardian` is** (call 28) — never learned.
