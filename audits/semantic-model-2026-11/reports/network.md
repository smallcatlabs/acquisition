## 2. Transitions

**Send (GET/POST) through `acquire_send` (`choke.rs:418`)**: loop { rails.halted? → `Halted`; !wanted → `Cancelled`; limiter wait>0 → sleep clamp(50ms,1s), continue; key = `serial_key(route)`; permit = gate.acquire(key).await; re-check halted, wanted, key unchanged, wait==0; else drop permit and loop }. Then (GET) `bearer.token()` read **after** admission (`:1049`); None → `StaleBearer`, permit dropped by return. Deadline taken once (`:1059`), `carry` + body both bounded by it (`by_on`, `ratelimit.rs:126`). `finish_send` (`:823`): observe headers → rekey gate → if transport Err and counted, `note_lost_send` → drain body under deadline → `verdict_of` → `classify_response` → `record_completed` (journal line, rails.record, ring) → return. GET 401 that is not a block → `bearer.rejected` (`:1073`) **while permit still held**.

**HEAD probe (`head`, `:555`)**: `admit_bearer_url` (off-origin → degrade route, no send) → `acquire_head` (exclusive permit, `gate.rs:213-230`: a queued HEAD stops all later ordinary grants until active drains) → token read → send → observation branches: blocked/unreachable → only `observe_blocked_head_429` if 429, route untouched; 429 → `observe_probe_429` (hold + establish-or-degrade); else `observe_probe` (Full → `Policy`, anything else → `Degraded` 60 s). 401 → `rejected` under permit (`:734`).

**Limiter endpoint state machine**: Unknown →(probe Full / declared no-probe GET with headers) Policy(state_key); Unknown →(headerless 2xx on declared route) Policyless; Unknown/Policy →(failed probe) Degraded{until}; Degraded →(until ≤ now, read-time) Unknown; Degraded →(`forget_degraded` at login) removed; Policy →(same name, new shape) history cleared; Policy →(different name) `PolicyMismatch` error, state unchanged.

**Gate**: Ordinary permit admitted iff `active.len() < 2`, policy not active, no HEAD active or queued ahead. `rekey_policy(route→policy)` renames live permits and waiters atomically (`gate.rs:105`).

**Rails**: `record` → sends+1 → maybe set blocked (persist) → maybe unreachable → maybe tripped (tripwire on; persist) → maybe ceiling → one `unannounced`. `reset_tripwire` (`:697`) writes disk first, then clears tripped, dormant, blocked, unreachable, ceiling_tripped, unannounced (ceiling still "met" via count, `:557`).

**Refresh single-flight (`valid_access_token_once`, `refresh.rs:373`)**: under `shared`: fast path if token has >5 s left (`:399`); no refresh token → NotLoggedIn; dead-grant mark → NotLoggedIn (`:414`); flight with same generations → Waiter; else become Owner (new flight id). Owner: POST outside `shared` → if rejected grant and flight still current → `mark_refresh_failed` (`:482`) → `finish` → `finish_refresh` (`:535`): under `shared` install tokens, close flight, publish; then keyring+index under `credentials`; then keyring word under `shared`. `RefreshOwnerGuard::drop` (`:55`) publishes `REFRESH_OWNER_ABANDONED` and clears the flight only if `finish` never took the sender.

**401 handling (C87)**: `reject_access_token` clears the session's token keyed by token value (`daemon.rs:712`); job then `land_rejection` → `persist_rejection` rewrites the keyring entry without the access token, only if generations unchanged and keyring was `ok` (`refresh.rs:298`). `StaleBearer` → `valid_access_token` outside the permit → one retry (`kinds.rs:968`, probe `:825`).

**Commutation**:
- COMMUTE: `reset_tripwire` × `mark_refresh_failed` (disjoint fields, both persist whole struct under one `state` lock). `observe` on policy A × `observe` on policy B (different state keys). Two `rejected(token)` calls for the same token (second is a no-op, `daemon.rs:716`).
- IDEMPOTENT: `rejected(token)`; `mark_refresh_failed` (returns false on repeat); `declare_policyless`; `begin_stopping`; `reset_tripwire` (modulo disk write); `rekey_policy` after the first.
- ORDER-DEPENDENT: `reject_access_token` vs `install_tokens_locked` (reject-then-install: new token stands; install-then-reject of the *old* token: no-op; install-then-reject of the *new* token: session emptied again). `record(block)` vs `acquire_send`'s post-admission halt check: a send admitted before the block's `record` goes out (acknowledged in `choke.rs:17-27`). `observe_impl` with a shape change vs `install_retry_hold`: hold then shape-change keeps `retry_hold_until` (it lives on PolicyState, not history) but clears history; shape-change then hold same result. `verify_state` then `with_config_and_clock` (see 3). `install_retry_hold` then `observe_impl` establishing the route: the hold lands in `retry_holds` only, `PolicyState.retry_hold_until` stays None → `retry_after_secs` in status is None though the route is held (`:699-711` runs before the state exists); the reverse order sets both. `probe_429` orders them deliberately (`:445-451`), `observe_landed` for a GET 429 also (`:544-546`) — both fine; only the blocked-HEAD-429-then-later-probe order shows the gap (status only, pacing correct).

## 4. Findings

### 4a. Nondeterminism

1. **Verified. Block vs concurrent admitted send.** With `MAX_ACTUAL_SENDS = 2`, send B passes its post-admission `rails.halted()` check (`choke.rs:437`) and is on the wire when send A's `record_completed` sets the block. B lands and is journaled after the mark; if B is also a 4xx-block, `s.blocked.is_none()` is false so the mark keeps A's cause. User sees two journal lines after one "SENDS STOPPED". Acceptable per C129's comment but unpinned as a two-send scenario.
2. **Verified. Gate `rekey_policy` under `debug_assert` only** (`gate.rs:113`). If two different route keys are live and one learns a policy name already in `active_policies` (reachable only for a no-probe route, `league`, whose first GET runs under route key `league@acct` while a probed route already active under the same policy name — or the mixed-scope case in 4c.3), release builds silently drop the invariant; the first permit drop removes the policy from `active_policies` (`:206` debug only) while the other permit is live, so a third same-policy send is admitted concurrently. Two-in-flight on one policy is exactly the N6 hazard. **Suspected reachable only if `/account/leagues` shares a policy name with a probed route** — the ground truth would say.
3. **Verified. `wait_for_refresh` ordering**: waiters subscribe to a `watch` (`refresh.rs:424`) whose value is set once by `send_replace`; a waiter that subscribes after `finish_refresh` set it reads it immediately — fine. But the flight is closed (`:597`) *in the same critical section* that installs, so a caller arriving after is an Owner of a fresh flight even though a valid token was just installed? No: the fast path (`:395-401`) runs first and returns the installed token. OK.
4. **Verified. Dispatcher pacing vs choke pacing are two readers of one limiter** (`dispatch.rs:218` and `choke.rs:427`). The dispatcher sleeps `min(d, 1s)`; the choke `clamp(d, 50ms, 1s)`; a job can pass the dispatcher's check and re-wait in the choke after a response lands in between. Observable only as `wait_ms` on the journal line. Benign.
5. **Verified. `HashMap` iteration reaching output**: `statuses` sorts policies and endpoints (`limiter.rs:743-770`); `refresh_failed` status joins sorted (`rails.rs:757-764`); `degraded_endpoints`/`policyless_endpoints` sorted. None leaks order. `reject_access_token` uses `values_mut().find` by token value — unique token, so order-free.

### 4b. Invariants enforced by hope

1. **Invariant 1 — verified structurally held.** Only `crates/acquisition-transport/src/lib.rs:110,148-162` constructs a client; `tools/arch-check.sh:394-396` holds the dependency edges; daemon has reqwest as dev-dep only (`Cargo.toml:56`; the one production-looking use, `mockggg.rs:1204`, is under `#[cfg(test)]` at `:1158`). Three properties the transport doc itself says are held "by review, by no check" (`lib.rs:30-34`): single caller of `Production::new` (`choke.rs:259` is the only one), no reqwest item in the public API, no timeout on the client. A grep check for `reqwest::` in `pub` items of the transport crate would close two of them cheaply.
2. **Invariant 3 — verified: a closed decision table.** `Verdict::of` (`rails.rs:348`) is one total function over (status, header presence, `BlockShape::of(body)`), and `classify_response` (`choke.rs:146`) is one total function with `block` first. The callers (`kinds.rs:1237`, `auth.rs:300-340`) act on `verdict`, never re-read the body. But `BlockShape::of` (`rails.rs:273`) is substring matching (`"cloudflare"`, `"nginx"`, `"error 1015"`, phrase `"ray id"`) on a lowercased body of unbounded size; GGG JSON echoing a user-chosen name "Cloudflare" is narrowed only by `!has("x-rate-limit-policy") && !has("www-authenticate")` — a GGG 404 JSON body containing "cloudflare" on a route whose headers were stripped would be judged a block and set a **persisted** mark. Pinned by C129's wire-table rows only for the documented shapes.
3. **Invariant 5 — verified held by type.** `Secret` has no `Serialize`, `Deref`, `AsRef`; `expose` is private (`auth.rs:62`); `Prepared` has no `Debug` (`transport lib.rs:70`); `TokenResponse`/`KeyringEntry` have redacting `Debug`. No token in `JobInfo.params` (probe params are `{route,url}`, `routes.rs:176`; whoami payload holds username only, `kinds.rs:736`). Journal `SendReport` carries no header map, only `response_headers_snapshot`'s allowlist (`policy.rs:~440`), which excludes `authorization`. **One hole, verified**: `Secret: Deserialize` with `#[serde(transparent)]` plus `KeyringEntry: Deserialize` means `serde_json::to_value` is impossible but `Clone + PartialEq` are public — fine. No disk path found.
4. **C22, C150 — "Pinned: nothing yet", verified unpinned.** C150 (proxy env vars) rests on reqwest's default behaviour under `default-features = false`; no test sets `HTTPS_PROXY`. Suspected OK (env proxies are read by reqwest regardless of the `system-proxy` feature) but nothing in the gate would notice a reqwest change.
5. **C2, C4, C15, C48, C49 — unpinned by ruling; C49 partly held**: `reject_access_token` keys on the token not the account (`daemon.rs:712`), but `mark_refresh_failed`/`refresh_failed` key on `username` outside the session layer (`rails.rs:719`, read at `refresh.rs:414` with `session.username`). A rename (refresh returns a new `username`, `refresh.rs:565`) leaves a dead mark under the old name forever in rails.json; `clear_refresh_failed` at login/logout uses the new name. **Verified by reading; suspected in effect** (needs a rename plus a prior dead grant).
6. **"Callers must" comments**: `Wanted` — "a send already admitted is never called back" (`choke.rs:81`) — by construction. `CompletedResponse.protocol` "only ever set on the token path" — held by the `keep_protocol_body` flag with exactly two literal call sites (`:1036` true, `:1066`/`:1092` false). `expect("landed responses have a policy parse result")` ×3 in `head` (`:614,619,650`) and `unreachable!` at `:755,:948` — true by control flow, not by type; `#[allow(clippy::too_many_arguments)]` ×2 is where a struct would make them typed.
7. **A never-sent request is journaled, counted toward the ceiling, and paced as lost — verified.** `Secret::authorize` failing (`auth.rs:71`, a token that is not a valid header value) yields `result = Err(INVALID_BEARER)` at `choke.rs:1062`/`:601`, which `finish_send` treats as a transport failure: `note_lost_send` (`:846`), a journal line with `error`, `rails.sends += 1`, and for a HEAD a 60 s degrade. Nothing left the process. Improbable input (GGG would have to issue a token with control bytes), but the journal oracle "counted == (method != HEAD)" would then pin a send that never happened.

### 4c. One fact in two places

1. **`retry_holds[endpoint]` vs `PolicyState.retry_hold_until`** (`limiter.rs:196` vs `:187`). Both written by `install_retry_hold`; `wait_for` reads the max of both; `statuses` reads only the latter. Authoritative for pacing: the max; for display: the policy's. They disagree when the hold lands before the route is established (blocked HEAD 429, `observe_blocked_head_429`): status shows no `retry_after_secs` while the route is held. Verified.
2. **`rule.state[].hits` vs `history`**: `next_safe_send` gates saturation on `hits` (server), `window_frees_at` dates it from `history` (local), `simulate` seeds the gap. By design (invariant 2). But in `observe_impl`'s `PolicyMismatch` arm (`:623-629`) the counted send is pushed to `history` (`:589-596`) and **not** `assume_counted`, unlike the parse-error arm (`:617`). At 299/300 a mismatched response leaves `hits = 299`, so the next send goes immediately. Verified in code; suspected in effect (requires GGG renaming a policy mid-lifetime).
3. **`endpoints[k] = Policy(state_key)` vs `policy_state_key(policy, account)`** (`:111`). A policy whose rules change scope (all-`Account` → mixed) changes its state key from `name@acct` to `name` with the same `policy.name`, passing the mismatch check (`:636` compares names only) → a second `PolicyState` under `name`, the old one orphaned in `statuses` with an empty endpoint list and keeping the daemon `is_live`. Suspected (never observed on GGG).
4. **`tripped` on disk vs `tripped`/`dormant_trip` in memory** (`rails.rs:436-438`). One file field, two in-memory fields chosen by `ACQ_TRIPWIRE`. `status().halted` and `halted()` read only `tripped`; the CLI's offline reset reads the file. A user with the tripwire off sees `halted: None` while rails.json says tripped; `acq daemon diagnose` only checks parseability (`verbs/diagnose.rs:403`). Verified; documented as H3-F3, but two interpreters of "is the world halted".
5. **Three send counters**: `Rails.sends` (every record), `ChokePoint.sends` ring (last 100), journal lines. All written by `record_completed`, no CAS needed; they agree modulo the ring's bound. The limiter's `violations` is a fourth, read by no one.
6. **Keyring entry vs session** (C135): the entry mirrors the session at save time; `persist_rejection` re-syncs on 401 but is skipped when `keyring != "ok"` (`refresh.rs:308`) — a session saved under `saving` at the instant of a 401 keeps the rejected bearer on disk for the next lifetime. Verified gap; the log line at `:336` names the consequence only for a failed save, not for the skipped one.

## 5. Refactors

**PROVABLY EQUIVALENT**
- Replace `expect("landed responses have a policy parse result")` ×3 in `head` by destructuring `sent` once into `Option<(status, policy, retry_after, raw, headers)>`: the `Option` is `Some` exactly when `completed` is `Ok`; a type check removes three panics.
- Fold `install_token_floor_hold` into `install_retry_hold` with a `RetryAfter`-shaped argument: both compute `now + RETRY_BUCKET_PAD(+…)` and `max` into `retry_holds`; `spec.rs`'s C131/C19 tables establish equivalence (the floor hold omits `BUFFER`, so the table would need the 1 s difference accepted or kept as a parameter).
- `SendReport.ok` derived from `status`/`error` at the journal writer instead of passed: `record_completed`'s match (`:969-975`) is a pure function of `(result, protocol_failure)`; the journal goldens hold the wording.
- Make `keep_protocol_body` a method split (`post_form` calls `finish_token_send`): two literal call sites, type-checked.
- Replace `ProbeError`/`SendError` `Display` duplication of `STALE_BEARER`/`CANCELLED` with a shared inner enum: wording goldens pin it.

**TRUST ME**
- *Drop the `retry_holds` map and keep only `PolicyState.retry_hold_until`.* Breaks on: a blocked HEAD 429 (`cf-mitigated`, no policy headers) on an Unknown route, then `reset-tripwire` within `Retry-After`: with the map gone there is no `PolicyState` to hold the route and the next probe goes out inside Cloudflare's window (pinned today by `observe_blocked_head_429`'s test).
- *Run `assume_counted` on `PolicyMismatch` as on parse errors (4c.2).* Differs on: an established `stash-request-limit` at `hits = 29/30`, then a response carrying `x-rate-limit-policy: stash-request-limit-v2` with full valid headers: old behaviour sends the next GET at once; new behaviour holds it one window. New is the C19-consistent one; the change is a spec-table row.
- *Promote the gate's `debug_assert!`s to hard errors or returns.* Differs on: the `league` first GET under route key `league@A` live while `character-list@A`'s policy `…-request-limit@A` is also live and the leagues response names that same policy: old = silent double occupancy; new = panic or refused rekey. Needs N39's policy name to decide.
- *Key the dead-grant mark by uuid instead of username (4b.5).* Differs on: pre-uuid session (restored from an index row without uuid) meets a 400 on refresh — no key to mark under; old marks by name.
- *Write the journal line before the token POST (owner's "Not doing").* Differs on: a refresh whose transport fails after the server counted it: today one line with `error`; before-send it would be two lines or a line without status, and the journal oracle `counted == (method != HEAD)` and "first send per route is HEAD" would need the open-line shape.
- *Check `admit_bearer_url` inside `head` before `acquire_head` is already the order; moving the GET's origin check after admission to match C87's "read after admission"* — differs on nothing observable but would add a wait before a refusal; keep as is.
- *Prune `retry_holds` entries whose `until` passed* in `wait_for`/`is_live`: differs on nothing observable today (bounded by routes×accounts); only memory.
