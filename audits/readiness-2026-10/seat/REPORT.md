## 1. Before touching anything

### What the brief told me (the brief)
Acquisition is an inventory tool for Path of Exile; `acq-mcp` is its MCP server. One account, `GERWARIC#7694`, is in the store: a copy of the person's real collection (~50 MB) with their prices. No login and no daemon exist in this world; calls needing the game's API will say they cannot reach it. Every call goes to a mock API and the store under W (the brief). None of this is counted as something the README or tool told me.

### What the README told me (written before any tool call)
- **Can do:** download stash tabs and characters to a local store; search offline (a query language, trade-site URL translation), describe/show items; set prices (with undo, `--if-revision`); render forum shop pages to paste; keep a league fresh via a sync policy and plans; run jobs through a daemon. MCP has 25 tools, listed by name in "Your agent", grouped: store reads, pricing/shop, sync policy/plan, jobs.
- **Needs what for what:** store and pricing tools need no daemon and no network ("The store and pricing tools need no daemon"); fetching tools need the daemon, and against GGG `acq-mcp` never starts one — the person must (`acq auth check`, or `acq auth`). Login is "a person's act at a terminal" in a browser on GGG's page; the token lives in the OS keyring.
- **Person must do before an agent can use it:** install the three binaries together; add the `mcpServers` entry with the path to `acq-mcp`; for fetching, log in with `acq auth` and have a daemon running (`acq auth check`). For the mock, `ACQ_PROVIDER=mock acq auth` and the env knob; `ACQ_STORE_DIR` in `env` must match the CLI's.
- **What I would not call without asking:** anything that spends the person's GGG rate budget or changes state they own — `apply_plan`, `submit_job` (and any fetch), `set_sync_policy` (a realm is written whole; naming only one league drops Standard), `cancel_job`, `price_set`/`price_clear` on things they did not ask about. Prices are the person's own; in this run T4/T5 ask for specific writes and their cleanup.
- **README gaps noticed already:** it points at `CLI-REFERENCE.md`, `AGENTS.md`, `decisions/<area>.md` and source files for knobs — pointers I cannot follow here. It documents the CLI verbs' flags but not the MCP tools' arguments. It names no MCP-side way to pass `--account`.

### What `open` told me (call 1)
- **The instructions** (call 1) add to the README: the server says which provider it is on ("Acquisition (provider: mock)"); a starting move ("Begin with search and no arguments"); that the query language and every answer's keys are explained by `describe` by name, in sections (fields, answer, trade, pricing, daemon, store) with sizes ("the whole is over 100 KB"); that a refusal is an `isError` result "with readings and offers", and "any request an answer holds is sent back as printed"; that `refresh_plan` adds a running daemon's quote without starting one.
